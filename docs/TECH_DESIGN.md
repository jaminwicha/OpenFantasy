# OpenFantasy — Technical Design Document

**Version:** 0.1 (vertical slice) · **Engine:** Godot 4.4.1 (.NET) · **Language:** C# (net8.0)

## 1. Architecture Overview

One Godot project, three logical layers:

```
┌──────────────────────────────────────────────────────────┐
│ Client (Godot scenes/nodes, thin)                        │
│  rendering · input capture · interpolation · UI · audio  │
├──────────────────────────────────────────────────────────┤
│ Net (Godot ENet transport + binary protocol)             │
│  client: send inputs, apply snapshots                    │
│  server: collect inputs, tick sim, broadcast snapshots   │
├──────────────────────────────────────────────────────────┤
│ Sim (pure C#, engine-free, deterministic)                │
│  world state · fixed ticks · combat · AI · progression   │
└──────────────────────────────────────────────────────────┘
```

**Doctrine compliance:** authoritative gameplay is a custom deterministic
simulation (`src/Sim`) that never touches Godot types — no nodes, no physics,
no floats from render frames. Godot is presentation + transport only.

## 2. Simulation (`src/Sim`)

- **Fixed tick:** 20 Hz (`TickDuration = 50 ms`). All gameplay time is
  measured in ticks (`int`). The server accumulates real time and steps the
  sim in whole ticks.
- **Determinism:** integer/fixed-point positions (world units = 1/32 tile,
  stored as `int`), seeded `XorShift64` RNG owned by the world, no
  wall-clock, no dictionary-order iteration over gameplay-relevant state
  (entities live in sorted containers / stable lists).
- **State:** `World` owns `TileGrid`, `Dictionary<int, Entity>` + stable
  ordered id list, spawners, tick counter, RNG. `Entity` = players & mobs
  (discriminated by `EntityKind` + `ClassId`/`MonsterId`).
- **Input model:** clients send `InputCommand { seq, moveX, moveY, abilityId,
  targetId }`; the server applies the latest input per player each tick.
- **Combat:** ATB gauge per entity (0..1000 fixed). Abilities are data
  (range, power, atbCost, mpCost, kind). Damage formula per GDD §5.2 with
  variance from the world RNG.
- **AI:** finite-state (Idle → Aggro → Return) with proximity aggro, leash
  radius, and melee/ability use through the same ATB rules as players.
- **Verification hooks:** `World.StateHash()` — FNV-1a over canonical entity
  state each tick; used in tests and net desync checks.

## 3. Networking (`src/Net`)

- **Transport:** `ENetMultiplayerPeer` (UDP), default port **24565**, but the
  protocol layer is hand-rolled binary over raw ENet packets
  (`MultiplayerPeer.PutPacket`/`GetPacket`) — we do not use Godot's RPC or
  `MultiplayerSynchronizer` (keeps sim engine-free and the wire format ours).
- **Topology:** dedicated listen server. Same binary runs as:
  - `--server [--port N]` → headless authoritative server
  - client (menu → join `host:port`, or **Play Solo** = spawn in-process
    server on loopback)
- **Messages** (binary, little-endian, 1-byte opcode):
  | Op | Dir | Payload |
  |---|---|---|
  | Hello | C→S | protocol ver, account name, class id |
  | Welcome | S→C | player entity id, world seed, current tick |
  | Input | C→S | seq, move dir, ability, target |
  | Snapshot | S→C | tick, state hash, entity create/update/remove list |
  | Chat | C↔S | channel, text |
  | Event | S→C | damage numbers, deaths, level-ups (for presentation) |
- **Snapshot cadence:** full-relevance (whole zone) delta-less snapshots at
  10 Hz for slice scale (16 players + ~40 mobs ≈ small). Interest management
  is a documented post-slice upgrade.
- **Client smoothing:** entities interpolate render position toward the last
  snapshot at a fixed smoothing rate; local player uses immediate input
  echo (position still corrected by snapshots — server wins).

## 4. Client (`src/Client` + `scenes/`)

- `Boot.tscn` → main menu (name, class, host/join/solo) → `WorldScene`.
- `WorldRenderer` builds a `TileMapLayer` from the same world JSON the server
  loads (both sides share `WorldData` loader — clients never trust their
  copy for gameplay; it is render + prediction hinting only).
- `EntityView` (Node2D): sprite + name label + HP bar; positions lerped.
- `Hud` (CanvasLayer): FF6-style panels — HP/MP/ATB, hotbar, chat log +
  entry, target frame, damage-number popups from Event messages.
- Scenes stay thin: every script is glue that reads net/sim state.

## 5. Data & Content (`data/`, `assets/`)

- `data/world.json` — tile grid (RLE rows), spawn regions, safe zone, POIs.
- `data/classes.json`, `data/abilities.json`, `data/monsters.json`.
- **Schema validation:** `DataValidator` checks every file at load (required
  fields, ranges, cross-references ability/monster ids) and fails fast with
  a readable error. Server refuses to boot on invalid content.
- `assets/` — original placeholder pixel art (PNG) generated by
  `tools/gen_assets.py`; regenerate with `python3 tools/gen_assets.py`.
- World map authored by `tools/gen_world.py` (deterministic layout for the
  Verdance March region) → `data/world.json`.

## 6. Persistence

Slice: server writes `save/characters.json` (per account name: class, level,
xp, gil, position) on disconnect + every 30 s autosave. Post-slice: real DB.

## 7. Testing & Verification

- `tests/` — xUnit-free lightweight self-test runner (`--selftest` flag on
  the shared assembly entry): determinism test (same seed + same inputs ⇒
  identical `StateHash` across 1000 ticks), combat math cases, data
  validation cases, XP curve cases.
- Manual playtest loop: solo mode, then 2-client LAN join; capture
  screenshots + server log + periodic state hash lines.

## 8. Performance Budget (slice)

- Server tick ≤ 2 ms at 16 players + 64 mobs (integer sim, no allocation in
  the hot loop beyond message buffers).
- Client 60 fps on integrated GPU; snapshot apply ≤ 1 ms.

## 9. Directory Layout

```
OpenFantasy/
  project.godot            # Godot 4.4 project (forward_plus → gl_compatibility)
  OpenFantasy.csproj/.sln  # Godot.NET.Sdk/4.4.1
  docs/                    # GDD, tech design, slice plan
  src/Sim/                 # pure deterministic simulation (no Godot refs)
  src/Net/                 # protocol, server host, client connection
  src/Client/              # node scripts (thin)
  scenes/                  # Boot.tscn, World.tscn
  data/                    # world/classes/abilities/monsters JSON
  assets/                  # generated placeholder art
  tools/                   # gen_assets.py, gen_world.py
  save/                    # runtime server saves (gitignored)
```

## 10. Key Trade-offs

- **Hand-rolled protocol over Godot RPC:** more code, but keeps the sim
  engine-free, the wire format inspectable, and determinism testable
  headlessly. Accepted.
- **Zone-wide snapshots, no delta compression:** wasteful at scale, trivial
  at slice scale; the message layer isolates the change later. Accepted.
- **Integer fixed-point sim:** slightly awkward math, but cross-platform
  determinism without float traps. Accepted.
