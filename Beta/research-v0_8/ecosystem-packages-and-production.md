# Selective ecosystem, extensible packages and production proof

Research date: 8 September 2026. This bounded review reads the current GameDevAIEcosystem source contracts/manifests and Beta's final technical design. It supplements the [original ecosystem audit](../architecture-decision-review-2026-09-08.md#7-the-ecosystem-useful-after-removing-friction). It did not execute model comparisons, install integrations, synchronize global files or validate a playable package.

## Use the ecosystem as selected help

**Retain the ecosystem's small, relevant skills, portable handoff artifacts and evidence conventions; keep heavyweight generation pipelines optional.** It is an instruction/tooling environment, not evidence that Beta's runtime already exists. Its value is preserved project knowledge, repeatable checks and discoverable tooling. The number of installed skills, orchestration stages or model brands is not an outcome metric.

The earlier audit found conflicting vendor assignments, forced implementation handoffs, an unsupported weighted confidence threshold, stale language examples and inadequate visual verification. These were concrete instruction defects, not proof that any model had lost innate ability. Current source documents now explicitly favor interchangeable leads, bounded readiness probes and separate correctness/playability/experience evidence. Treat that as a correction in policy, still awaiting comparative execution evidence. [Current operating contract](/Users/alucinor/Workspace/Projects/GameDevAIEcosystem/.specs/agent-operating-contract.md), [maintained readiness skill](/Users/alucinor/Workspace/Projects/GameDevAIEcosystem/skills/confidence-check/SKILL.md).

The flexibility contract gives each game authority over its simulation, art, schemas and production pipeline. Godogen's maintained overlay explicitly disables implicit invocation and requires an intentional full-game-generation task. Beta should therefore use a relevant API reference, migration checklist or rendered verification workflow when it helps, without inheriting a platformer's movement rules, geometric art identity or a mandatory scaffold/generate/commit ceremony. There is no obligation to salvage a cumbersome workflow. [Flexibility contract](/Users/alucinor/Workspace/Projects/GameDevAIEcosystem/.specs/flexibility-contract.md), [Godogen overlay](/Users/alucinor/Workspace/Projects/GameDevAIEcosystem/skill-overlays/godot-godogen/SKILL.md).

## Roles and persistence of useful learning

Codex and Claude should each be able to own design, engine implementation, tooling, content or review from beginning to end. Assign by available context, callable tools and observed results. Interchangeability means either can resume from project artifacts; it does not mean simultaneous conflicting edits or an obligatory model switch. Antigravity's default remains bounded maintenance—formatting, link checks, inventories and asset organization—with behavior changes returned to the responsible lead. [Repository role policy](/Users/alucinor/Workspace/Projects/GameDevAIEcosystem/AGENTS.md).

Artist agents own editable sources, visual consistency, animation and accepted reference interpretation. Engine builders own importing, playback, interaction and performance. Their shared contract includes dimensions, pivots, frame/action names, contact points, semantic state and style version. A beautiful reference scene is not an exported sprite sheet; a working importer is not art acceptance. Independent critics inspect the delivered motion and behavior. Human style/enjoyment judgments remain separate from virtual-playtest observations. [Maintained art direction](/Users/alucinor/Workspace/Projects/GameDevAIEcosystem/skills/game-art-direction/SKILL.md).

Keep each task's file ownership, requirement IDs, decisions, known failures, commands and evidence in ordinary project files. Reusable user preferences belong in maintained ecosystem skill sources and mapped installations; Beta-specific lore, dimensions and approved images stay in Beta. The source README and manifests record backups, targets and hashes. Their checks establish instruction integrity, not model performance. Later manifests can supersede earlier hashes, so drift checks must use the latest recorded update for each target. This review inspected the records but did not independently rerun synchronization. [Skill-source policy](/Users/alucinor/Workspace/Projects/GameDevAIEcosystem/skills/README.md), [initial adaptation manifest](/Users/alucinor/Workspace/Projects/GameDevAIEcosystem/manifests/2026-09-08-portable-skills.json), [phased-plan validation record](/Users/alucinor/Workspace/Projects/GameDevAIEcosystem/manifests/validation-full-scope-phases-2026-09-08.json).

Do not equate a README describing an MCP integration with a connected tool. Qualify the actual host with a small generate/inspect/revise/export/import cycle, including editable source and failures. CLI/API fallback may be better than a broad but unreliable MCP wrapper. Documentation changes do not activate services or establish live Antigravity IDE integration.

## Typed packages must demonstrate useful extension

Beta selects one namespaced definition/process system for first-party, in-game-created and community content. A useful package must add playable meaning—for example, a herb, its growing conditions, a brewing process, a status interaction and a resident opportunity—through public contracts rather than private engine edits. Cosmetic reskins alone do not prove this capability. Larger additions can reveal missing verbs; introduce those as reviewed, tested engine capabilities rather than escaping into unrestricted package code. [Beta package and AI contract](../spec-v1_0/TECHNICAL_DESIGN.md#9-narrative-knowledge-branches-and-packages).

The ecosystem supplies a useful manifest model: stable content/package IDs, schema and compatibility versions, canonical hashes, dependencies, provenance, editable metadata and validation results. Adopt these responsibilities, not its exact Maker-level schema. Beta also requires effect bounds, knowledge filtering, actor permissions, material conservation and historical interpretation. Syntactically valid JSON is not proof of those semantic properties. [Content lifecycle specification](/Users/alucinor/Workspace/Projects/GameDevAIEcosystem/.specs/content-sharing-online-services.md).

A native or managed code extension remains engine code with corresponding review and version obligations. A separate .NET `AssemblyLoadContext` handles dependency/type loading; Microsoft explicitly describes its isolation as name-based, without binary isolation. It should not be presented as a sandbox that makes arbitrary community C# safe or deterministic. Ordinary packages remain typed data and bounded operations under one authority. [Microsoft AssemblyLoadContext documentation](https://learn.microsoft.com/en-us/dotnet/core/dependency-loading/understanding-assemblyloadcontext).

Save compatibility is broader than keeping the current map loadable. Pin the definitions, rules, generator versions and accepted artifacts required by living instances, ongoing jobs, NPC memories and every promised historical interval. Upgrade/removal needs impact analysis, backup-copy migration and verified continuation, compatible retained interpretation or an explicit refusal. Missing content cannot quietly become a null item or a replacement person. Immutable historical prefixes and origin claims also prevent a package update from duplicating resources or rewriting another branch. These obligations come from Beta's selected design; the ecosystem's simpler replay/level contracts do not already implement them. [Persistence and archive contract](../spec-v1_0/TECHNICAL_DESIGN.md#4-transactions-saves-and-recovery).

## Optional AI and accepted-result replay

Development agents and optional in-game AI are different systems. Development agents edit reviewed artifacts. Runtime AI receives only the principal's allowed observations, beliefs and context and proposes typed results. It cannot directly award goods, change anatomy, expose a secret or create canonical history. The authority validates a proposal against the current revision and commits the accepted output, provenance and effects once.

Replay uses that stored accepted result; it never asks the provider to reproduce an old answer. A delayed result must revalidate current conditions, and a duplicate response cannot create another reward. Provider timeout or absence uses declared local behavior. Offline play must remain coherent. This is an implementable contract, not a claim that a particular model always follows a schema or generates suitable narrative. [Beta authority/knowledge contract](../spec-v1_0/TECHNICAL_DESIGN.md).

## Retained operational and creator gates

The generation-evaluation specification usefully separates deterministic correctness, packaged gameplay and perceived experience, and says it is an evaluation specification rather than an installed runner. Preserve that distinction. A second region and asset family produced through the same workflow are stronger production evidence than a manually repaired first showcase. Count accepted assets, interactions and narrative continuations after cleanup/rejection/rework, with measured time and actual tool cost; raw generated-file counts obscure production burden. [Evaluation specification](/Users/alucinor/Workspace/Projects/GameDevAIEcosystem/.specs/game-generation-evaluation.md).

Retain these cases, all **unrun** in this review:

1. **ECO-01 — workflow/handoff:** repeat frozen tasks under minimal and curated skill profiles with the same model/version, tools and resource budget. Measure defects, repair, unnecessary pauses and observed output. Separately let either lead resume from the same project artifacts. Keep failed trials; do not infer universal model superiority.
2. **ECO-02 — artist/engine throughput:** produce a second coherent kit with motion, weather/wear cues and interaction metadata. Verify editable round-trip, actual native-scale playback, owner acceptance and independent engine integration. Record cleanup/rejection cost and tool availability; rendered evidence must expose a deliberately broken pivot or frame mapping.
3. **ECO-03 — package/history:** install a meaningful external typed package; create residents/jobs/items and historical branches, then upgrade, remove and restart. Validate every retained era and custody claim. A deliberately incompatible definition must fail before mutation, preserving a usable original save.
4. **ECO-04 — AI/offline:** accept one proposal, lose the response, retry, restart with the provider disabled and replay. State/results must match without duplicate effects. Submit a stale or secret-dependent proposal and verify rejection without disclosing hidden facts through errors or logs.

Use failures to simplify the workflow or strengthen the relevant contract. Do not compensate for unreliable authoring with more mandatory agents, or claim production readiness before these artifacts exist.
