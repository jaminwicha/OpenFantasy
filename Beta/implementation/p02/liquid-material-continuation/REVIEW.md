# Integration and independent review

## Source findings during integration

Root found that accepting any generic continued Production context would weaken geography admission.
The inline runoff validator checks retired ingredient revisions against custody and rejects geographic
identities that alias Production roles. Generic material compaction intentionally retains live rights
and source retirement ranges; it does not retain every retired lot revision or fully retired command,
lot and consumption identity. Checking only current segment records would let a generic cut conceal
facts that geography originally rejected.

The runtime worker confirmed the revision information loss and the identity-role case. A proposed
maximum-revision observation alone could not preserve the identity constraint and was superseded before
qualification. The accepted design carries bounded opaque fixed-domain/context qualification from the
actual validated closing capacity. Reservoir application adds the exact validated geometry catalog.
New nested decoders require that qualification, alongside opaque material evidence where applicable.
Generic context injection and unevaluated new geometry are not admitted. No unbounded identity ledger,
invented historical ingredients or duplicate material authority is introduced.

This is an integration finding and design correction, not an executed failing test. The final runtime
does not change Production or add a parallel historical revision ledger.

## Independent source review

One native critic independently reviewed the frozen runtime, affected architecture and subsequent test
additions. The critic found no further runtime blocker after the qualification correction. The review
checked private proof construction, actual closing inventory/Production hashes, fixed-domain/context
validation, every nested decoder, exact reservoir geometry qualification, ordinary reconciliation,
pending funding/aggregate headroom, stale plans, unchanged bounds and complete-world/transport guards.

The critic identified two missing branch proofs: nested V5 completion evidence and the distinction
between capacity-only decoder dependencies and exact reservoir geometry dependencies. Both received
direct cases. The V5 case uses real funded construction and its actual final work action, with another
real completion as the wrong-proof control. The geometry case first decodes shifted equal-capacity
geometry under the legacy standalone interpretation, then requires continued decoding to refuse it.

Review of the new construction fixture found the reused-reservation setup defect described in
[FAILURES.md](FAILURES.md). The correction adds a separate unused reservation only in the optional
original authored admission; assertions retain the six real construction units under their original
reservation. No funding rule or default construction fixture behavior changed.

The first full regression found an old test that expected generic requests to reject later in
preparation. The independent critic checked the revised boundary test: it asserts the new earlier
constructor refusal, keeps the legacy V1 encoding refusal, exercises valid V3 reconstruction from an
actual qualified capacity, and preserves the original bytes. No gate was weakened. Runtime files
did not change after the first successful build; the final rebuild changes only this existing test.

The critic performed source review only. Astra owns the executed build, behavioral, compatibility and
preservation checks; none of these substitute for full-world persistence or human acceptance.
