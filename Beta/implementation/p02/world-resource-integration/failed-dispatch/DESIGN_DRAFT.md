## Ready-to-apply design (no code was written to disk)

The design keeps one HP/MP/XP owner and adds one world-level owner, `WorldResourceHistory`, admitted only in profile25.

- **Owner shape.** `WorldResourceHistory(anchorAdmission, ActorResourceHistory history, records)`. The anchor is the exact fresh care-admission progression at world sequence 0, bound by requiring `AnchorAdmission == world.AdmissionVersion` and matching world/branch. One `WorldResourceCauseRecord(commandId, kind, actorId, variationPermille)` per batch, with kinds `EncounterAbility`, `QuestReward`, `RestorativeTreatment`. Records must align one-to-one with batches by command identity.
- **Envelope exhaustion.** `Append` throws a new `WorldResourceContinuationRequiredException` deriving from `Exception`, not from the exception types processors translate into `Unavailable`. It therefore surfaces at the host instead of becoming a silent rejected action. Durable admission stays disabled; the continuation obligation is host-authenticated rollover with accessible prior causal evidence.
- **Causal admission** (`WorldResourceAdmission.Validate`, called from the `WorldSnapshot` constructor after care validation). Replays from the basis while tracking each actor's head, so historical attacker stats come from replay rather than a retained claim. Per kind: ability batches recompute `ComputePhysicalDamage(attackerHead.Attack, target.Defense, ability.PowerTenths, record.Variation)`, require the ability pin to equal `ability.Version`, require a scenario grant for the attacker, and require an MP change equal to `ManaCost` whenever it is nonzero. Reward batches must match a participation whose `CompletionCommandId` equals the batch command, with amount `Reward.Experience` and pin `Reward.Version`. Treatment batches must match `CareTreatment.CommandId` and `WorldSequence`, evidence `TreatmentId`, amount `RestoredHp`, and `After.CurrentHp == HpAfter`. Finally `History.ValidateCurrent(progression, revision)` proves the complete replayed actor set.
- **Seam removal.** Delete `WorldCareAdmission.ExpectedHpAfterLastAttack`. In `WorldEncounterActionAdmission.Validate`, profiles through 24 keep the original `CurrentHp != last.TargetHpAfter` check unchanged. Profile25 instead requires the batch at `last.WorldSequence` with command `last.DecisionCommandId`, kind `EncounterAbility`, matching attacker and `VariationPermille`, a damage change with `Before/After.CurrentHp` equal to `TargetHpBefore/After` when `Damage != 0`, and an MP change equal to `ManaSpent` when nonzero. Later HP is then explained by replay, not by dropping the check.
- **Writers.** `WorldEncounterActionProcessor.Resolve` builds `ResourceChangeBatch(sequence, 0, choice.DecisionId, [damage, mp])` with cause `(choice.DecisionId, ability.DefinitionId, ability.Version)`, skipping no-op transitions. `WorldCareProcessor.Administer` appends the treatment batch from `restoration.ActorTransition`. `WorldStepProcessor.DecideImmediate` appends a reward batch for completed delivery quests using the action's position in `batch.Actions` as the command ordinal, including zero-XP rewards, and restores `previousHistory` in the existing rollback block. `FitsCompleteCandidate` and both final `WithState` calls pass the history.
- **Snapshot and codec.** Add `resourceHistory` to both `WorldSnapshot` constructors, `WithState`, and `WithPending`, required iff `Care` is present. `WorldSnapshotCodecV25` gains one trailing field and a 24-field reader; the size guard adds the new codec maximum. The new codec frames anchor hash, basis sequence, basis progression bytes, `ActorResourceHistoryCodecV1` bytes, and the record collection, all bounded, with canonical re-encode. `WorldAdmissionValidator.ReadResourceHistory` registers commands as cause references and pins each cause definition under its kind's role.
- **Tests planned.** In-memory `WorldStepProcessor` journey methods beside the Sqlite ones in `CareWorldFixture`: real bites to defeat, acknowledge, administer, resumed attack, canonical restore at each boundary, forged cause, omitted MP or damage effect, reordered changes, stale basis, failed reconciliation rollback, and a profile24 journey asserting no history and unchanged bytes.
