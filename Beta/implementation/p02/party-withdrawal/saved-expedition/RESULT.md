## Implemented boundary

- `--prepare-party-withdrawal` opens an eligible source exclusively, checks the exact transition and
  unused cause, then writes a create-only canonical request. The report identifies its saved head and
  request hash. Preparation changes no saved world and reserves no future eligibility.
- `--enable-party-withdrawal` boundedly reads that request and calls the existing verified-copy
  publication owner. A stale source, malformed request, existing destination or already-migrated
  source is refused. There is no automatic repinning, overwrite, retry or implicit fresh admission.
- The solo opener verifies the exact original genesis before recognizing a recorded40→41 head with
  matching world/branch/admission. Different seed/name/roster selections remain refused without
  rewriting the save. Fresh adventure creation remains40.
- The maintained native roster probe selects the collective observation codec when that owner exists;
  legacy observations retain their old encoding. This diagnostic path builds, but has not yet run in
  the saved cooperative expedition. No new launcher or parallel authority was created.

The frozen rules, root/action/step formats and storage schema are unchanged. Source, original history
and ordinary state are owned by the existing migration/recovery contracts. The next implementation
