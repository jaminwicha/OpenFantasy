# Lifecycle repair integration checks

These are lead review questions, not a completion claim. The worker owns its assigned source until
terminal delivery; final source and fresh qualification must agree.

- A fill moves goods/money once and increments one issuer revision once, regardless of how many
  siblings become superseded. Shared supersession references require the actual same-step fill;
  they must not duplicate an accepted command identity as several independently owned causes.
- Issuer withdrawal retains its real command identity, delivery and command position. Wrong actor,
  invalid delivery, changed-content retry, already-closed terms and stale/current-world conditions
  preserve owners. Withdrawal is neither work nor payment nor expiry.
- Canonical outcomes retain actual acceptance action order for currency replay. Runtime methods
  create canonical order; constructors/decoders reject a permutation rather than normalize it.
- Every carried quote remains exact, open or terminal. Closing capacity reserves all sibling
  closures; archived quote/create/fill/withdrawal/split identities remain occupied after reopening.
- No old profile or ProductionV12 capability is widened; profiles29/31 and the513 old tests remain
  exact. Refinements are confined to the unaccepted new paid-world format.
- Immutable64-resident admission proves the128-issuer bound sufficient for this development world;
  no revision pruning, reset, roster expansion or new scale acceptance is inferred.
- Final evidence runs once the worker is terminal and integrated. The prepared final runner keeps
  all existing time limits, deduplicates managed cases, exports actual saves, kills real processes
  and checks independently mutated paid SQL rows. It has no retry or skip switch.
