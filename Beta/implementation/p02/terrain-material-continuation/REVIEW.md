# Integration and independent review

## Qualified terrain boundaries

During source integration, Astra found that a terrain observation retained in a Production context
was insufficient by itself to qualify later generic cuts. A generic material action could conserve
inventory while violating a geographic identity or representation-custodian rule. If its Production
were cut before registry reconciliation, the offending active record could disappear while the old
terrain observation survived.

The runtime now requires every terrain-capable cut to come from the actual validated registry.
Public Production cut methods and ordinary internal capture paths reject that capability; the
registry's internal terrain cut retains its fixed catalog, exact active bindings and selected
material/construction capabilities. Ordinary typed material actions remain available, and their
complete candidates must reconcile with the registry. No extra historical identity ledger, invented
retired ingredient revision or parent-owner chain is introduced. This is an integration source finding,
not an executed test failure.

## Independent critic scope

One native independent critic first identified three useful targets: empty-cell demotion still changes
both storage clocks and retains its cause; coarse coalescing can recreate lots outside the selected
moved intervals; nested liquid codecs must not downgrade terrain-capable Production to V4/V5.
The implementation and new tests address those boundaries.

The frozen-runtime review found a mandatory-history lookup bypass in the crafting wrapper. Its optional
caller callback was wrapped inside a non-null local predicate, so the lower continued planner could not
tell that permanent historical lookup had been omitted. A completely retired old command could then
appear available after a cut. The wrapper now requires an actual non-null caller lookup for continued
owners before composing it with registry roles; inline behavior remains unchanged. A targeted test
retires the old craft and checks omitted lookup, occupied historical lookup and a fresh-command control.
This was a source finding. The independent critic reviewed the exact fix and targeted regression:
all four outputs of the old craft are consumed by real actions, the actual registry is cut, the old
command/output roles are absent from the active owner but retained by permanent lookup, and the same
remaining raw stock supports a fresh command. No test manufactures the historical disappearance.

The completed review also checked the qualified generic-cut refusal, imported/current cross-allocation
retirement, fixed catalog and empty active-cell corruption controls, full partition replay, both storage
clocks, the real 512-operation boundary and actual V6 construction completion. The optional genesis
stock is explicitly authored before real work; the default fixture remains unchanged. The critic found
no remaining blocking source/test issue in this bounded scope. The review was read-only and ran no
builds/tests; executable validation, compatibility and preservation remain the integration lead's work.

Native implementation and test workers have disjoint ownership. The test worker additionally owns an
optional construction fixture variant admitting finite terrain stock at original genesis before real
quest/work actions. Existing defaults stay unchanged. Astra owns integration, execution, docs and Git.
The external Claude route was not automatically retried and no credit savings are inferred.

## Replay cost and independent delta review

The first full Core run completed with 1,534 passes and one diagnostic-prefix failure. Its unchanged
512-operation terrain test passed in 694.17 seconds. Source inspection found that every representation
or construction proof hash rebuilt a Production snapshot and replayed its earlier material history.
Before changing that implementation, the separate [WIP checkpoint](qualification/replay-optimization-checkpoint.json)
preserved all owned source, tests, docs and evidence, excluding unrelated predecessor staging.

`ProductionMaterialCodec.HashReplayPrefix` now observes the already replayed values using the same
private canonical field writer as ordinary encoding. It retains the same bounded, identity-sorted
batch/claim/lot collections, chronological operations, checked cumulative counters and byte limits.
Only replay uses this internal observer; it neither constructs an admitted snapshot nor bypasses the
complete owner's structural and authority validation. Each operation still checks exact rights,
identities and intermediate raw-plus-produced capacity.

The same independent critic reviewed this consequential delta and its transient-state implications.
No blocking source issue remained: full-owner validation retains all batch/claim records, sequential
spending conserves output rights and revisions, and `Created`/`Occupied` plus per-operation capacity
checks cover transient identities and stock. Existing different-derived-prefix construction evidence
and intermediate-overflow adversaries remain required execution controls, alongside all mixed terrain
journeys and the unchanged 512-operation case. No public unchecked helper, new trust boundary or
test-access API was added. Timing comparisons are local observations, not production performance gates.

The native runtime worker's optional performance follow-up failed at the account usage limit; Astra
implemented this bounded change directly. The independent critic completed source review only. No
automatic external paid retry, silent model substitution or claimed credit saving was involved.
