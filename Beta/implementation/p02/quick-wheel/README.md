# Native quick actions

11 September 2026. A bounded P02 action-access increment toward the living UI supplement,
not a completed interface or phase. The frozen 23-file baseline and all 181 requirements remain.

## What is now playable

V, right-stick click or Actions opens four broad cardinal slots: Talk, Gather, Craft and Give.
Original provisional SVG glyphs lead; short labels, exact target/cost, effort and blocker details
remain visible. No selection is assumed on opening. Pointer, directions, D-pad or deliberate
stick input inspect a choice. Enter, controller A or Confirm submits the inspected offer.
V/Escape/Start/right-stick/B/Close only cancels. The center is an inspection label, not a button.

The wheel owns player input but never changes host time policy. Running time continues; an
existing pause persists. Focus loss or controller disconnect cancels. Held navigation requires
release before walking. HUD focus returns to a valid prior control. Known blocked farm actions
remain inspectable; a profile with no production domain has no Craft slot. These are admitted
farm meanings, not general knowledge/capability discovery or a finished action catalog.

`FarmQuickWheelModel` owns stable slots and pinned identities without Godot dependencies.
`FarmQuickWheel` owns the editable scene and inspection/confirmation presentation; `FarmWheelDisc`
owns radial drawing/navigation. The existing input router owns context, and `FarmGame` sends the
captured, session-issued offer through the existing host. No core/save/clock/IPC change was needed.
Refresh may update revisions and availability but cannot silently replace the inspected person,
plant, operation or scope. A stale submitted action remains a host rejection, never a retry.

## Retained failures and corrections

- The initial focused test wrongly expected a five-swing oak to be depleted after one harvest.
  The assertion now requires its actual remaining availability and incremented node revision;
  the stale captured command must still reject without duplicating goods.
- Native traversal initially used action availability as arrival geometry. Initial low effort
  let the probe walk past the oak. It now stops at the existing public reach predicate and waits
  for ordinary effort recovery. No production reach/cost/recovery rule changed.
- A stick tilt moved focus from the disc to the disabled confirmation button. Four explicit
  self-neighbours retain cardinal selection while a separate Tab cycle reaches buttons.
- Injected pointer coordinates were transformed as embedder coordinates. Viewport-local
  `PushInput(event, true)` now delivers the intended Control position with mouse-enter setup.
- Controller A reached the disc but did not match `ui_accept`; actual bindings contained only
  Enter/keypad Enter/Space. Shared default setup adds the missing A binding, also for native
  buttons. No pre-GUI bypass was introduced.
- Several rendered attempts lost native window focus. Reports retain that loss and the cancelled
  wheel/unchanged action. The fixture now waits for startup activation, requests focus once and
  verifies actual focus. It never reacquires focus during the journey. Concurrent native process
  activation is a possible contributor, not a proven explanation for every earlier failure.
- The integrated input probe's Talk command at commit 68 expected Wren revision 18; the actual
  pre-command state had revision 19 and the receipt was `RevisionConflict`. The retained save and
  [analysis](qualification/failures/input-revision-analysis.json) confirm this. The probe now
  waits for settled player/target revisions matching the displayed offer before its one press.
  Existing 8-second waits and rejection rules remain intact; failure diagnostics include the offer.
- Rendered action-probe review found a stale viewport frame labeled dialogue but showing the
  pack. The capture-only follow-up awaits an actual completed frame before reading the texture.
  The original report/images are retained; their behavioral assertions do not certify that image.
  The follow-up builds but its rendered journey failed approach after losing focus before dialogue;
  the corrected dialogue capture remains unqualified.

A later integrated attempt timed out in editor import at its unchanged 180-second limit. A separate
diagnostic import was manually stopped after roughly 203 seconds without completing initialization.
Its retained sample shows editor theme initialization; concurrent high machine load and heavy memory
compression were observed, but the exact cause is not proven. No successful import is claimed for
that run. Finish native integration when the host can execute it within the existing bounds.

A duplicate engine exit callback was also caught by compilation and merged into the existing
cleanup callback. Earlier import/editor-settings and rendered-travel uncertainties remain in
the prior packets. Nothing here closes them or excuses an engine error from a zero-exit process.

## Remaining scope and reusable lessons

dynamic device prompts, general target/confirmation flows, rich item icons, accessibility/scaling,
localization, physical devices, co-op invalidation and native novice/expert usability still require
their planned work. Current farm glyphs and scene art are provisional. The owner’s criticism of
basic gameplay/poor graphics remains open; this wheel is one usable access route, not a solution
to the complete game’s complexity or accepted art/animation/audio production.

All 14 UI acceptance cases remain `not_run`; contracts gain partial evidence only. P00/P01/P02
exits and P03–P14 remain required. No gates or scope were reduced. Upstream ecosystem commit
`f1e5fb1` preserves narrow native binding, radial focus and viewport-injection lessons. Four local
skill files were synchronized with checked hashes/backups; no external model was invoked.
