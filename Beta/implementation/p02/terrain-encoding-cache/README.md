# Immutable terrain encoding cache

Full recovery of the completed native cargo circuit exceeded its 30-second opening requirement.
A standalone process opening a disposable byte copy with the exact expected genesis measured
36.0548802 seconds before the cache and 18.766909 seconds afterwards. Both openings replayed and
authenticated the entire same journal. This is one local Debug comparison, not a production or
cross-platform latency qualification. The native cargo presentation and opening gates remain open.

`TerrainRegionCodecV1` now retains canonical bytes by exact immutable snapshot object in a
`ConditionalWeakTable`. A mutation creates a new snapshot; equal bounds/revisions never identify
cached contents. The cache retains no live world owner, and each exported byte array is a distinct
copy. Its original encoding logic, every field/version, malformed-input refusal and complete
recovery contract remain unchanged. The architecture is documented in
[identity and determinism](../../../Runtime/docs/architecture/identity-and-determinism.md).

[Checks](CHECKS.json) retain source/assembly hashes and measurement provenance. All 1,756 Core
cases pass, including existing independently generated byte/malformed corpora and new concurrent
export, buffer mutation and equal-revision/different-excavation counterexamples. The complete
[test report](core.trx) and [runner report](core-report.json) preserve that evidence. The suite ran
in the integration checkout with the native cargo work present; it does not accept that work.

The measurement program is retained as [measurement.cs](measurement.cs). It references the built
Core/Hosting assemblies and their existing SQLite dependencies, opens only a disposable copy,
and times exact-genesis `SqliteWorldAuthority.OpenExisting`. The source save is preserved in the
delivery checkpoint recorded by CHECKS.json; original source-save bytes and unrelated staging
were never modified. Before/after logs are [baseline](baseline.log) and [cached](cached.log).
