# Complete-root baseline for partition design

This accepted increment measures real existing state before selecting a partition format. It supplies
a retained Hosting diagnostic and focused tests, not the integrated PLAN-STATE prototype. One current
adventure movement and two actual funded construction histories execute through existing Core/SQLite
owners. No simulation law, world profile, schema, default launch or permission changes.

These are different admitted workloads, not a controlled speed comparison between formats. The legacy
profile nests its quest basis inside one field; a changed outer field does not mean every contained
fact changed. Current profile40 field positions are checked against `WorldSnapshotCodecV35.EncodeComplete`:
movement changes space, residents, time/revision/steps, gathering, liquid cells, pacing and encounter
lifecycle. First funded work changes the corresponding advancing fields plus construction; completion
also changes inventory, production and reservoirs. Installed structures are reconstructed through the
construction binding, so an unchanged spatial-components field does not imply unchanged collision geometry.

The current one-human construction case uses ordinary dialogue, acceptance and owned wood delivery
to earn the actual quest reward and fund Wren. After closing reading, the existing NPC controller moves
and works through ordinary committed commands; both construction cases install a real object after
200 work units. Every receipt is applied, and current quest/progression hashes remain unchanged during
the subsequent work. The fixture controls which actions are submitted; this is not native input or an
autonomous offscreen proof. The 512-step bound stays fixed.

Both databases reopen with the exact final content hash. Legacy revision269 reopening plus hash
verification takes 301.200 ms; current revision252 takes 733.978 ms. Current reopening explicitly pins
the original genesis. These intervals include verification, not just database reads. The legacy case
retains its existing explicit copied quest-to-construction transition. Neither case partitions state.

## Consequence for the architecture

There is measurable byte reuse, but storage chunking alone cannot meet the frontier requirement.
Advancing one step updates more than the moved actor. The actual constructor/step dependencies also
prevent arbitrary slicing of the current world. The [comparison](../../PLAN_STATE_COMPARISON.md) now
maps resident time, due work, construction funding/access, source-frame completeness and transaction
ownership to explicit extraction responsibilities. Test the typed-aggregate/spatial-index candidate
first, with whole-local aggregates retained as the comparison alternative. This is investigation order,
not approval of a new persistent format.

Next prove real actor/cargo crossing, bounded absent detail, funded offscreen work, atomic publication,
stale/missing dependencies, crash/retry and original-history replay under one authority. Then decide
the persistent representation. Cold/warm partial loading, commit costs, resident memory and due-work
age remain unmeasured here. No LANG, city/frontier, native/human, independent review or P02 gate closes.
