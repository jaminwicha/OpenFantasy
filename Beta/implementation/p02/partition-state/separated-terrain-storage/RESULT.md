## Implemented design boundary

Immutable terrain remains in the original full genesis plus exact hash-keyed archives. Mutable head
and checkpoints encode all supported nonterrain owners and complete terrain references. This changes
storage interpretation only, with explicit schema dispatch; it never reads a later profile as five.
Recovery first performs complete ordinary replay and verifies every stored image, receipt and identity,
then can evict terrain for selected construction. It is not partial authenticated recovery.

The serialized owner pins a captured locality and legacy byte-envelope delta, copies genesis identity
reservations without retaining its terrain index, and uses real durable history for each selected work
batch. Ordinary interventions hydrate/admit the exact current root and invalidate the interval. During
work there is no terrain archive read; final installation may load geometry for complete admission.
Old/new heads, identity reservations and outcomes publish in one existing SQLite transaction. No second
writer or simplified work simulator is allowed. Test actual gifts, a partial return and final completion
with original history; corrupt/missing terrain must refuse recovery, not become empty cells.
