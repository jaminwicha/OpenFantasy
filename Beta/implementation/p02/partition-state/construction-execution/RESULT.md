# Shared construction execution and detached candidates

Ordinary `ConstructionPlanner` and the new detached `ConstructionWorkPreparation` now use one
`ConstructionWorkKernel`. Its source/geometry adapters preserve the existing authorization, funding,
actor/tool/revision, reach/access, work, identity, capacity and material-completion sequence. The
[extraction comparison](EXTRACTION_CHECK.json) checks the exact decision body after explicit adapter
and result substitutions; live adapters read the same world facts. Original completed spatial candidates
and standalone material-continuation completion evidence remain required by their ordinary paths.

`ConstructionSiteEvidence` qualifies reach and prospective placement from an actual admitted project.
It retains the exact actor/structure population, terrain references, shape/access pins and support
interpretations without retaining the scene, terrain cells or prospective complete candidate. Work can
reuse that qualification while geometry remains unchanged. Changed population/body/position, terrain,
support, project geometry or required access invalidates it. New command-derived identities still pass
spatial identity/catalog checks, and final work checks world/material/historical identity occupancy.

Detached nonspatial facts copy identity keys and reserved encounter-family prefixes instead of retaining
`WorldIdentityIndex`, whose terrain layer owns region references. The result contains actual coupled
inventory, production and construction candidates plus the proposed structure on completion. It is not
an admitted world, earned time, physical/load result or durable receipt. No existing format, schema,
source content, default launch or ordinary action law changes.

## Remaining integrated proof

Capture and exact-root freshness still require a complete admitted source. The detached API returns a
candidate for a selected advancing/hold context; it does not select that step, reconcile due processes,
charge time, perform complete physical/world admission or publish it. The 200-step comparison advances
its ordinary oracle each step. It therefore does not establish 200 autonomous offscreen commits.

Some continued production contexts retain actual excavation regions or terrain representation. Detached
capture explicitly refuses those contexts rather than secretly retaining their detail or deleting their
witnesses. Ordinary continued construction still uses the live adapter and passes its selected existing
regressions. Extending the detached material boundary and proving actual supported current-profile
execution remain required; no implicit migration or profile 41 feasibility is claimed.

This increment supplies a real shared decision kernel and detached coupled completion, not merely
another geometry helper. The [prototype contract](../../../PARTITION_PROTOTYPE_CONTRACT.md) still requires
admitted owner inputs without full-root capture, stable actor/cargo ownership and spatial membership,
actual cross-owner transfer, earned scheduling, physical admission, durable atomic publication and
original-history recovery. The metadata remains complete/local and memory bounds are not production
scale proof. No benchmark, native/independent/human/platform or full phase gate is closed here.
