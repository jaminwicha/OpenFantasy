## Outcome and measured limits

The internal `WorldResidentExposureBasis` now stores actual unchanged resident metadata and personal
base ages plus the common earned exploration duration. Successors require exactly the next advancing
ordinal and check the greatest base age for overflow during selection. Custodian lookup reads unchanged
metadata; `Residents` materializes ordinary `WorldResident.Experience` results. Capture/intervention
starts from admitted materialized ages, so neither repeated reads/preparation nor rebasing double-charges.
Holds do not advance the basis. Work, gathering/regrowth and publication ordering are unchanged.

Warning-free preflight builds discovered 23 Core and 15 Hosting cases. All 38 passed (seven new), with
no skips: Core 3.359 seconds and Hosting 13.384 seconds, each under the 180-second managed bound. The
source/binary manifest contains 1,929 inputs and matches the tested build. Existing geometry/routes were
unchanged and retained their lawful cardinal/controller movement; saved-world tests again verified the
same actual gift, actor intervention, partial return, completed material/structure and first/final
commit faults. Core tests retained the 200-step source-world/terrain collection proof and actual due
regrowth. Every materialized result agrees with ordinary encoding and replay. Overflow, skipped/reused
ordinals, varied ages, day rollover and rebasing have focused witnesses.

Two actual fixture residents, 200 selected steps, warmed exact operations, capture and final
materialization included; Apple M2, macOS arm64, .NET 8 (full environment and command records in preflight/):

| Resident representation | Allocated bytes | Observed milliseconds |
| --- | ---: | ---: |
| Explicit resident copies each step | 88,000 | 0.218 |
| Basis, read only at the end | 13,400 | 0.132 |
| Basis, materialize every step | 113,696 | 0.329 |

These are one sequential small-population diagnostic, not timing thresholds, peak residency, scale or
storage benchmarks. The every-step consumer costs more: do not advertise this as an optimization of
complete-root publication. The useful architectural condition is explicit: future persisted actor
owners can avoid per-step exposure writes only if a legal timing/membership owner is retained and
materialization is actually deferred. The current ordinary publisher still writes complete residents.
No general runtime default or persisted format was changed. Do not adopt a per-field owner merely
because this two-resident calculation allocates less when reads are deferred.

The existing full construction diagnostic reported 8,548,272 allocated bytes for continuation versus
17,269,832 for ordinary execution, excluding capture/assertion hashing/reconstruction. It remains a
bounded implementation comparison; no cross-packet speed improvement or production claim follows.

No failures or retries occurred in this packet. Two managed test commands, zero native/expedition runs,
and zero runs exceeding the 180-second focused budget; therefore no long-run failure classifications
apply. Build/discovery are separately recorded preflight commands. API call count and average context
remain unavailable, not zero. Prior full-Core timeouts and all earlier failure evidence remain unresolved
and retained. Required independent review is unrun under the owner pause.
