# Material custody and issuance across continuation

Status: verified standalone material-domain increment; complete-world integration remains open.

This increment extends the [continued material owner](../production-continuation/README.md) with
explicit V4 gathering, raw transfer and reserved-delivery composition. A material cut must not freeze gathering or make transferred
stock unusable. It remains part of the [coordinated material/care protocol](../restorative-recovery/MATERIAL_CARE_CONTINUATION.md),
whose complete-world, dependent-owner and durable publication gates remain mandatory.

## Required behavior

- Preserve one canonical inventory/production composition. Typed operation evidence describes actual
  changes; it must not become an independent inventory or an arbitrary grant/delta API.
- Distinguish source capacity from actual issuance. Gathering owns its monotone issued cursor and
  actual tool, work, spatial and step rules; completed excavation has a separate issuance contract.
- Transfer and source delivery move existing exact intervals. Split identities, reservations, protection,
  definition pins, custody/storage/lot revisions and historical identity occupation remain exact.
- Crafting and consumption can use lawfully acquired/moved stock. Raw ancestry retires once; output
  partitions conserve every imported and newly produced interval.
- Preserve existing V1/V2/V3 interpretations. New structural capabilities require explicit admission
  and canonical interpretation, rather than silently broadening old continued owners.
- Cuts preserve live rights and absolute counters without retaining recursive owners. Complete-world
  and geography/care consumers remain guarded until their full joined invariants are qualified.

## Implemented contract

`ContinueMaterial` selects a bounded ordered history and a context with exact live rights, storage
baselines, admission pins and an optional actual gathering baseline. The typed adapters call genuine
gathering, raw transfer and delivery rules; craft and consumption join the same ordered history.
Replaying every operation proves intermediate combined raw/transformed capacity and exact final
owner hashes. Decoding requires exact context and opaque planner-produced issuance evidence; callers
must additionally run `ValidateForAuthority(actualInventory)`. Old V1/V2/V3 interpretations remain
separate. The [architecture reference](../../../Runtime/docs/architecture/production-continuation.md)
describes ownership, limits, formats and authority boundaries.

The source bridge uses the actual current source owner and exact deterministic idle advance. It does
not freeze the world hash across a segment or replace external effort spending. Refusals retain the
actual supplied source; unrelated material operations return no source replacement. These rules are
also documented in the [world composition reference](../../../Runtime/docs/architecture/world-composition.md).

The principal journey applies 13 actual operations across two cuts: three gathers issue nine units,
transfers and full/partial reserved deliveries preserve exact intervals, two crafts and four
consumptions retire six units, and three remain live. Actual world time enables effort recovery. A
separate 1,028-operation journey crosses the unchanged 512-entry limit twice, first proving refusal
at each full window, then continuing through an explicit cut. It preserves a protected survivor,
exact absolute revisions, source stock and historical identity refusal.
