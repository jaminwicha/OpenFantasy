# Independent review scope

Run one bounded independent review after implementation and lead integration checks, using the
approved exact `fable[1m]`, one-million context and Max effort. This file prepares the review;
it is not evidence that a model was dispatched or that anything passed. The executed packet must
pin the completed source, relevant project/skill inputs and actual finite time/usage limit.

Review the complete change against ASSIGNMENT.md, the implementation notes and WORLD_BINDING_REVIEW.md.
Read actual code and relevant pre-existing owners. Do not accept worker reports or test names as proof.
Remain read-only and return concrete counterexamples with source locations, suggested corrections,
remaining uncertain risks and a clear acceptance recommendation. Do not produce consensus wording.

Challenge these joins in particular:

1. Both authenticated approvals bind the same actual lot kind, definition pin, quantity, custodians,
   revisions and actors. Forged claims must not acquire authority, occupy another participant's
   identity or expose their outcome. Raw V1 bytes and unilateral policy semantics remain exact.
2. Whole/split movement preserves producing batch, output index, intervals, original producer,
   consumed ingredients and both raw/derived capacity. Installed or genuinely reserved construction
   outputs cannot become free goods. No arbitrary mutation may pass merely because totals balance.
3. Full replay and cuts preserve acceptance/command/child roles, including retired identities;
   current material state alone cannot replace historical occupancy. A candidate must pin both
   owners, and partial rejection must leave them unchanged.
4. Current plans select a standalone V10 ordered-history capability that excludes V9 complete-world
   production. Assess the assignment's explicit requirement to avoid a disconnected branch. Which
   executable steps and evidence can be reused by the coordinated world, and what validation would
   have to be rebuilt? Identify actual dead ends or duplicated authority, not just missing Host/UI.
   A standalone green test does not prove the full integration route.
5. Old codecs, capability selectors, continuation cuts and world admission must reject incompatible
   interpretations rather than silently gain/drop the new capability. Old fixtures cannot change.
6. Inspect the actual mixed craft/gift/consume/recraft/onward-transfer journey and more than one cut.
   Does it establish custody and lineage, including the negative cases, or only equal end totals?
7. Distinguish submitted claims, structural decoding, plausible matches, authenticated decisions and
   durable publication. Missing asynchronous offers, migration, Host, native and retained-world proof
   must remain visible; tests must not be relabeled to imply those outcomes.

The review may recommend retaining only reusable work pending a stronger world integration. No
acceptance gate or full-scope obligation is waived to fit the worker's budget or chosen design.
