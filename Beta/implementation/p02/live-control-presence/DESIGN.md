# Live presence and assignment custody

This increment binds the existing profile40 assignment boundary to authenticated established ports.
It is the host prerequisite for explicit actor selection, not a new rendered control mode. No public
local, TLS or Godot actor-switching interface is admitted by this increment. Home actor and delivery,
old wire bytes, private readers and the existing return generation remain unchanged.

## Boundary and ownership

- A live request captures the exact accepted permission and original expired disconnect episode,
  including slot revisions. The host derives the grantee from the authenticated current port, generates
  a fresh assignment cause and sequence under serialization, and uses the existing Core adjudication.
  The request does not transfer credentials, ownership, custody or another character's private view.
- Saved Human state, a credential, a provisional port and an old disconnected port establish no live
  presence. Only completed authentication and final admission validation do. A returning owner's
  established transport precludes takeover even before its paid work reaches safe human restoration.
- Acquisition resets readiness, movement and unaccepted queued input. The grantee's home character
  remains human with its ordinary decisions and holds. Selected gameplay is a separate dependency.
- Exact assignment custody belongs to the acquiring port. A stale release or disconnect cannot affect
  a replacement assignment. Ordinary disposal relinquishes that custody without inventing a transport
  loss; actual grantee loss records only the grantee's original controller event.
- Successful owner return releases effective assignment immediately, including at an unsafe boundary.
  Previously accepted paid work retains its original command, attribution, costs and normal resolution;
  invalidation grants no new action and does not restart the absent owner's allowance.
- A newly attached live host releases saved active assignments through ordinary journal boundaries
  before play. Opening the database for inspection alone does not mutate its head. Graceful shutdown
  releases live custody; a failed/crashed host is reconciled on the next attachment, with no invented
  offline gameplay time or renewed original allowance.
- Conservative autonomous encounter and aftermath selectors exclude actors with active effective
  assignments; Core remains the final authority and no new autonomous policy is introduced.

## Validation plan

Use real profile40/schema12 journal state, actual PlayerAdmissionService and in-memory message
transport, original manual time and unchanged existing deadlines. Contrast unestablished, established,
returned, disconnected and replaced ports. Prove no mutation on stale/forged request and no host failure
from ordinary refusal; distinguish a refused acquisition from an authority/storage failure.

Retain actual paid combat work across owner return and host restart. Prove nonadvancing releases,
original permission/controller/custody preservation and exact reopen through complete journal replay.
Retain all 752 original tests/fixtures and 23 frozen specification files, plus unrelated predecessor
staging, under PRESERVATION.json. Run affected controller, player routing and effective-authority checks
with the same source-pinned, serialized build/test wrapper and bounds. No source edits during checks.

Core code, canonical rules/bytes and storage schema are unchanged; previous complete Core evidence
can be inherited only after comparing actual sources and binaries. Storage-only checks are inherited
only to the extent their source/test dependencies are unchanged. Changed Host behavior is tested fresh.
Keep original failed timing reports; a new pass does not explain a prior timeout. No native, TLS
selection, physical-device, process-kill, phase or production acceptance is implied.

## Remaining full selection contract

Preserve immutable home identity separately from a monotonically versioned selected actor. The
selection generation is not PlayerControlStatus.Generation (which deliberately remains zero/one).
Publish authorized view plus selection coherently; force a new publication even at the same world
hash; clear input and require deliberate Resume. Bind requests and responses before asynchronous
waits, so A-to-B-to-A cannot revive old commands, movement, readiness, menus or query results.

Do not blindly project LocalWorldView for another actor: it contains private inventory, wallet,
progression, quests and closed history. Keep private history independently scoped and existing
owner-only readers intact. Accepted actions retain original waiter/receipt ownership while selection
changes. All capabilities and the local/TLS/Godot, archive/reopen, crash and native journeys in the
[complete design](../co-player-control/DESIGN.md) remain required, with no reduced phase scope.
