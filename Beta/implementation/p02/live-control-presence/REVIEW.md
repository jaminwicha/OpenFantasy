## Findings and integration

host serialization; owner return invalidates custody before safe restoration; exact witnesses protect
replacement assignments; ordinary disposal differs from actual transport loss. Publication reconciles
revoked/replaced custody before its hash shortcut. Core still owns consent, episodes, eligibility,
accepted command obligations and canonical publication. Public actor identity, delivery, observations
and private history readers retain their original home binding.

- A separate revoke/regrant case checks the publication clears live custody/readiness/movement,

## Precise limits

The foreign release case uses an unestablished original-owner port. It proves refusal at establishment,
not established third-player custody isolation. Establishing that owner intentionally releases the
assignment, so a three/four-human fixture is required for the distinct foreign-live-player proof.
The established same-grantee stale witness and old-versus-replacement port cases are separate actual
contrasts. Full multiple-live-player actor-selection qualification retains the third-player obligation.

The actual received admission/transport boundary is in-memory. Permission setup and accepted combat
work are trusted journal preparation under a paused manual-clock host, not new selected-player wire
commands. The paid attack is retained across owner return and resolves with its ordinary resource and
readiness cost. Startup inspects an authentic active backup before attaching a new host; cleanup and
later exact reopen do not stand in for a real process-kill journey.

Actor selection generations, authorized selected views, A-to-B-to-A stale async results, consent/menu
navigation, TLS/Godot selection and native/human acceptance remain required. The internal custody API
must not be exposed as that completed interface. No profile bindings, Core schemas, clocks, movement
leases, test deadlines or acceptance thresholds changed.
