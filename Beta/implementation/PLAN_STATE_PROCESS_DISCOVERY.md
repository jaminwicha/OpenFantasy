## Resolved design constraints

1. **Discover after the relevant action effects.** The ordinary interpreter mutates tentative domain
   owners before expiry/transport/gathering/exposure/liquid processing. A directory captured before
   actions proves the source, not that a due list remains current. Bind candidate discovery to the
   effective post-action owners and renew downstream dependencies after earlier processes.
2. **Distinguish evaluation from successful completion.** Transport can record a lawful blocked stage
   and advance time with all stock/reservations conserved. Unavailable stock can prevent regrowth.
   Neither is permission to omit evaluation; neither requires freezing world time until success.
   Distinguish missing data, legal holds, capacity exhaustion, ordinary blocking and proposal exclusion.
3. **Use the selected interpreter's clock.** Offer/quote expiry uses advancing count, regrowth uses
   process intervals where pacing exists, transport uses its exact calendar step, and detailed liquid
   flow can use the accumulated process boundary. Tactical exposure can advance without a complete
   process interval. Commit sequence is never a substitute for those domains.
4. **Do not flatten distinct continuations.** Persisted excavation retains accepted command/outcome
   reservations and earns its interval only at terminal publication. Construction read slices are
   unpublished and disposable. Care, encounter lifecycle, controller and permission changes dispatch
   through separate laws. Queue transition order is not a replacement for these interpreters.
5. **Authenticate absence as well as presence.** A complete owner membership statement is necessary
   even when a known owner reports no due work. Missing owner data cannot appear as an empty result.
   The existing directory and full admission remain the source of completeness until an alternative
   index is qualified; there is no general persisted discovery frontier today.
