# Durable watershed network admission

12 September 2026. This P01 increment admits the [finite prepared network](../watershed-network/README.md)
into a complete composed world. It establishes retained macro ownership across ordinary actions and
exact recorded history. It does not close the geological requirements, a phase or any production gate.

## Contract and integration

`WorldWatershedNetworkAdmission.CreateGenesis` accepts only an unplayed profile-five construction
basis: revision zero, advancing steps zero and no reading hold. World, branch and realm match the
network. The admission pin incorporates the previous admission and complete network hash under its own
canonical domain. Actors, inventories, definitions, material provenance, progression, quests, calendar
and construction remain intact. This operation does not migrate or rewrite a lived profile-five/six save.

Profile seven nests a genuine profile-five basis and the exact network archive. It is a sibling of
profile six; the root cannot independently own both a single basin and a network. Earlier profile
interpreters and bytes are preserved. Step seven carries the existing action/receipt semantics.
Schema three, its exclusive SQLite owner, full journal, transaction boundaries and existing recovery
limits remain unchanged. Ordinary world steps retain the same immutable network object; snapshots,
restart and exact recorded-commit reads retain its bytes. No clock or separate authority is added.

The province, all member basin/formation/substrate/outlet/internal-face roles, and every shared face
enter the composed identity inventory. They cannot alias terrain, material definitions, actors, lots,
batch causes or command identities. Cached macro roles depend on the same macro and terrain references,
with scope checks on every root. These reservations grant neither extraction rights nor water custody.
The full snapshot still fits 16 MiB; the nested network still fits four million bytes. Oversized
compositions reject rather than dropping state or increasing limits.

The privileged operator `--create-watershed-network-world` reads bounded canonical basis/network files
and creates an explicit new save under the existing authority. `--execute-world-step` and
`--inspect-recorded-world` preserve/report its network. Reused/stale batches and an existing destination
reject. This is an offline trusted operator, not an authenticated network API or a default gameplay
save selector. The normal farm continues to select its existing profile and terrain.

The same-change [architecture reference](../../../Runtime/docs/architecture/world-and-geography.md#runtime-binding-admitted-network-ownership)
explains ownership, identity, persistence and remaining design boundaries in timeless terms. Frozen
specifications and earlier increment records remain unchanged.

## Next dependencies and scope

The next geography dependency is an explicit mapping from retained macro columns and ancestry to local
terrain scale and realization, with compatible boundaries and conservative material/resource custody.
The existing farm terrain remains physically authoritative; macro parcels cannot be mined just because
they are reserved. Contributor counts remain topology witnesses, not liquid volume, rainfall, storage
or a physically realized river/ocean. Fluid transfers require their own source/receiver and history rules.

Dynamic frontier admission, province/climate/coast/reservoir preparation, played-save migration,
geological evolution, historical travel, production streaming and cross-platform capacity/latency remain
open. The network envelope is not the final world's extent. No existing geography may be silently
rerolled or replaced on load. All 181 baseline requirements, 14 unrun full UI cases, P00/P01/P02 full
exits and the campaign through P14 remain intact. This increment adds no visible art or new terrain.
