# Quest farm content admission

`QuestFarmAdmission.CreateQuests(existingWorld)` reads embedded, exact-hash content and prepares the newly admitted components for the retained production farm. Its internal filesystem equivalent exists for source-tamper and byte-equivalence tests. It does not create a fresh farm, replay legacy save files, accept a quest, deliver wood, award experience, build a windbreak or publish a database.

The input must be the existing two-resident profile 3 farm with its exact production admission hash and recipe definitions. The existing Wren resident must retain the original name, home, wander radius and opening utterance. Current location, experienced time, inventory, gathering cursor and production history may have changed through real play. To compare original production definitions without colliding with the definitions already admitted to the root, validation uses a temporary gathered-state view of the same objects; that view is neither returned nor persisted.

The result retains all source rights, raw lots, current policies, storages and custody revision, adding exactly one empty six-unit project store owned by Wren and a distinct reservation identity. The project permits explicit controlled-actor deposits, while the world quest action decides whether a delivery satisfies the quest. Ordinary gifts and pre-existing Wren inventory are not quest completion. The existing production component is validated against the augmented custody, and the migration owner retains it unchanged. Project capacity is a count limit; this is not a placed structure or a construction mass admission.

`QuestFarmComponents.Admission` exposes a `WorldQuestAdmission` containing the manifest content version, new progression/quest definitions and only the new `QuestProjectCustody` specifications. The migration payload does not contain or replace old custody. The convenience `Inventory` property is a locally validated candidate for composition; the migration processor independently appends the new empty stores to the exact retained state. The admission bytes therefore remain independent of old-world movement, gathering and crafting progress for the same world and branch.

Both admitted actors receive new, explicit level-one, zero-XP, full-vitals progression. The player profile composes the original Squire base/growth with explicitly admitted Human zero modifiers. This new admission does not assert that species or class was previously present in the old body or paperdoll data. Wren preserves source `SpawnNpcs`/`Entity` defaults as **Unassigned**, with HP 1, MP/attack/magic/defense 0 and speed 1, no growth. These definitions do not grant equipment, abilities, anatomy, movement or language. Existing gathering effort stays pinned to gain ten.

The exact original level thresholds are retained as an integer table, including cap-ten residual XP behavior. The source reward 420 XP yields level 3, residual XP 38, HP 78 and MP 14 for the newly admitted Human Squire. The reward operation and its atomic application are separate core/world responsibilities.

Both personal Gil balances start at the original zero. A separate **authored finite reserve of 200 gil** funds the one local diagnostic quest recipient. The source implementation minted its reward without a payer; the reserve is an explicit correction, not Wren's hidden personal wealth. No currency item is inserted into bag capacity. Future additional players/quests need an explicit funding policy and admitted supply.

The unaccepted quest retains `wren_orchard`, “Wren's Saplings,” its offer, Wren as giver, minimum level one, the exact original wood item pin, six-wood obligation, 420 XP and 200 gil. The original turn-in line, “The wind can howl all it likes now. Thank you kindly.”, remains preserved in source and is withheld until a real structure supports that claim. It cannot truthfully announce a built windbreak while materials are merely delivered. The manifest explicitly retains this narrative gate. Source prerequisite/main/reward-item defaults and the complete source record remain preserved, though this narrow quest definition implements only its actual delivery obligation.

The upgrade admits no new wood and resets no gathering budget. An older save may already have consumed, given away, protected or reserved its usable wood and exhausted its finite oak source. Such a world can retain the quest definition while delivery is currently unavailable or impossible under this bounded profile. Admission must not pretend to guarantee a recoverable quest path by minting stock; the public action needs an honest unavailable state, and any future rescue funding, alternate source or conversion rule needs its own explicit admission. Ordinary offcuts are not silently reinterpreted as the exact raw wood item.

Class, level-curve and currency definitions use stable content IDs across seeds. Project storage, reservation, wallets, reward and quest bindings use the existing world and branch as a domain-separated seed; quest/reward IDs are world scoped because these values bind a concrete giver and reserve. Every new role rejects collisions with current root identities and other newly admitted roles. Historical-ID admission and publication belong to the migration owner.

The new manifest is `content/quest-farm/admission-v1.json`, SHA-256 `261e86948438c7bd8ad34e001c918c40053acedf82041a3f89909a54db095918`. All older manifests, source records and asset bytes remain unchanged. The existing embedded-resource wildcard includes this manifest and the new exact `Entity.cs.txt` source witness without a project-file change. The latter is an unchanged 4,096-byte extraction from `src/Sim/Entity.cs` in the preserved original archive, SHA-256 `9c24378d705934022a8f07c901a7f4ddcc2e1ee977488a956e4609da935222a3`; its archive hash and copy provenance are pinned in the manifest. No supplemental source executable is loaded.

The loader bounds the manifest at 16,384 bytes, requires the fixed four-record/five-witness/nine-threshold shape, verifies the full original closure through the prior admissions, matches each selected payload and pointer to its original JSON file, and verifies the exact source/default witness bytes. Missing, oversized and changed files fail closed. This is a deliberately fixed authored admission, not an extensible content editor accepting arbitrary replacement manifests.

`verify_admission.py` independently checks source payloads, archive extraction, all closure files, original wood identity, definition identities, integer thresholds and the first reward result; it writes evidence to stdout and executes no managed application. `QuestFarmAdmissionTests` covers the real walk/gather/craft state before admission, unchanged old state, empty project stock, exact source profiles/reward, separate finite funds, stable definitions and seeded instances, embedded/filesystem equivalence, wrong profiles/persona/admission, role aliases, tampered closure/default witnesses, and missing/oversized manifests. Managed execution remains coordinator evidence and must be recorded only after the shared build succeeds.
