# Portable finite gathering contract

The new `OpenFantasy.Core.Gathering` namespace implements admitted source extraction, banked actor effort and finite fixed-site regrowth. It prepares immutable candidates; only the outer world authority may publish them. It does not implement crafting, a quest ledger, construction, biological renewal, nutrition, currency, tool wear or generalized skill progression. See [SOURCE_CONTRACT.md](SOURCE_CONTRACT.md) for original behavior and intentional target corrections, and [ADMISSION.md](ADMISSION.md) for the actual authored farm profile.

## Public composition

- `GatherIntent(NodeId, ExpectedNodeRevision, ToolLotId, ExpectedToolLotRevision)` is a typed `WorldActionIntent`. Actor presence revision, control claims, world and branch remain in `WorldActionCommand`.
- `GatherNodeDefinition(DefinitionId, Kind, YieldDefinition)` fixes oak or berry source behavior and computes an exact version hash. `YieldDefinition` is a `CountedItemDefinition` identity/version pin. It is not a source claim itself.
- `GatherToolDefinition(Definition, Kind, Power)` admits one exact counted item pin as an axe or sickle with source power 1–3. Actual access still requires a live owned lot of that definition. Admission does not grant a tool merely because a definition exists.
- `GatherNodeState(NodeId, Definition, SourceId, UnitCapacity, Feet, Revision, NextUnissuedUnit, RemainingSwings, DepletedAtStep?)` retains one finite admitted source and its monotonic issue cursor. The node is a nonblocking interaction anchor, not a terrain obstacle or fake actor.
- `GatherActorWork(ActorId, Effort)` is identical for human-controlled and host-controlled actors.
- `GatheringSnapshot(WorldId, BranchId, AdvancingStep, Nodes, Tools, Actors)` defensively copies, sorts and validates those collections. `GetNode`, `GetActorWork`, `AdvanceStep` and `ValidateForWorld` use typed state; they do not read rendering or wall time.
- `GatherPlanner.Plan(WorldSnapshot, currentInventory, currentGathering, WorldActionCommand)` returns `GatherPlan` with `CandidateInventory`, `CandidateGathering`, `Rejection` and optional `SpawnedId`. These remain private until the owning transaction commits its complete world candidate and receipt.

The profile supports at most 32 nodes, 16 tool definitions and 64 actor work records per component snapshot. These are admission/qualification bounds, not instructions to drop excess persistent work or a claim of world-scale streaming capacity. Collection inputs reject duplicates and overrun before unlimited enumeration. Identities cannot alias incompatible local roles; shared node/item identities require exact version agreement. The outer world identity index validates cross-domain actor, source, anatomy, language, custodian and definition roles.

## Resource and work invariants

`GatherRulesV1` explicitly pins effort cap 1,000, gain ten per committed advancing step, cost 400 per swing and reach 448 subunits. The gain is the source level-one Squire calibration, not a universal character speed formula. Native admission starts both actors at zero; granting Wren the same work schema is authored target applicability. Banked effort allows two immediate accepted swings from 1,000, leaving 200; a cooldown would change the retained behavior.

An accepted swing consumes one remaining swing and exactly the selected owned tool's power in source units. It never rounds down output to fit source or inventory capacity. It creates exactly one lot at `EntityId.DeriveSpawned(command.CommandId, 0)` with source interval `[oldCursor, oldCursor + power)`. Inventory storage and custody revisions increment once, node revision increments once, actor effort decreases by 400. Source admission and tool lots are retained unchanged. Capacity, reservation, stale revision, identity collision or arithmetic failure rejects the candidate without partial extraction.

A live node must retain `RemainingSwings × strongest admitted matching tool power` units. A new/restored profile with an incomplete live-cycle reserve fails admission, avoiding a permanently visible node that can never finish. Depletion consumes the final swing: oak has five and berry four. It records the **action-start advancing-step ordinal**. At the end of that already-selected ordinary step, the ordinal advances once, contributing the first step toward renewal. Stump presentation applies while elapsed steps are less than 20; afterward the node is absent. The same stable node/source can regrow at elapsed 900 oak steps or 700 berry steps only if a whole next cycle at the strongest admitted matching power fits. The cursor never resets. If the reserve is exhausted, the node stays absent. Regrowth increments node revision; a derived stump-to-absent display change does not independently mutate its revision.

`AdvanceStep(nextOrdinal)` requires exactly current ordinal plus one and checked arithmetic. It restores eligible swings and caps effort without modifying the original snapshot. There is no offline accumulation or tactical-time interpretation. The world processor advances this component once at the end of an advancing batch, including one whose action opens dialogue. Held batches never advance it, and gathering is disallowed while a reading hold is active. The processor checks its evolving dialogue list so an earlier action in the same batch cannot open a hold and permit a later free swing.

## Admission and action boundaries

`ValidateForWorld` requires exact world/branch/advancing-step equality, complete actor work coverage, admitted tool item pins, one matching finite source/capacity/yield pin per node, and all current lots of a node source ending at or below its retained cursor. Unissued stock is valid; a live lot is not required to represent every admitted source unit. Cursor history prevents reused rights even if later typed operations consume or relocate issued lots.

`ResourceInteractionQueries.QueryAnchor` checks an admitted nonsolid cell, an admitted solid support cell directly below it and a cell-aligned floor. It works across retained region boundaries. This is one-cell point-anchor clearance, not a structural simulation or a resource-sized collider. Full actual actor clearance remains the existing spatial admission's responsibility. `Query` requires equal feet elevation and exact XY center distance ≤448; it traces terrain at the actor's actual doubled body-center height to the resource XY. No guessed resource height or manufactured actor body changes the sightline. Nonblocking resources can share a cell with an actor. Different elevation, missing dependencies, terrain blockage and out-of-range targets cannot authorize extraction.

The host authenticates current delivery before constructing/selecting a batch. The planner then checks current control before private inventory details, current actor/node revisions, resource reach, anatomical `Manipulation`, actual owned nonreserved tool lot and its exact version/kind/revision, effort, finite stock and destination capacity. `UserReserved` and explicit `ReservedBy` suppress tool use; being equipped is allowed. The planner checks current sequential inventory and gathering candidates, not stale starting inventory after another actor's action. A mismatched issued-interval/cursor pair rejects before constructing an overlapping lot. Private tool existence, ownership and revision failures use `Unavailable`.

The outer `WorldStepProcessor` must additionally reserve batch causes/commands/results and check current and historical spawned identities. A historical collision discards the extraction candidate; the ordinary selected step may still advance effort by ten. Same-node competing actors resolve in canonical actor order, so the second stale node revision rejects. Only durable authority completion produces a committed receipt; this component has no retry store or IO behavior.

## Canonical restoration and compatibility

`GatheringCodecV1.Encode` and `Decode` use the existing OFC framing version one. Top-level `gather.snapshot` contract version one includes exact work-rule bytes, world/branch/step, sorted nodes, sorted tool pins and sorted actor work. Each node includes its complete pinned definition, signed coordinates, finite capacity/cursor, revision, swing count and optional depletion step. All integer widths and enum values are strict; trailing data, unknown rules/version/tags, unordered/duplicate members, oversized data and invalid scalar/join invariants reject. The maximum accepted top-level byte length is 262,144, with smaller nested frame and collection bounds enforced before allocation. Re-encoding accepted data must reproduce the exact input bytes.

The optional component lives only in world profile two, using the root's explicit `WorldSnapshotCodec`, action and batch version dispatch. Existing world profile-one bytes remain frozen; loading an old save must not silently add empty component bytes, source reserves or a starter kit. Database schema version two and OFC/component contract version one describe different layers. The authored gathering world uses its own genesis/identity lineage and save path; this contract does not claim an automatic old-save conversion.
