# Gather/craft persistence review

10 September 2026 UTC. Independent bounded design inspection before the next feature changes. Reviewed the schema-2 SQLite store, composed world codecs/replay, source admission, local session, source gathering implementation and representative recipe/quest records. No builds were run for this review. The coordinator subsequently assigned Hosting codec/session implementation to this critic; those changes require their own tests and are not independently qualified by this recommendation.

**Retain the existing SQLite owner and schema 2. Add an explicitly versioned gathering world profile first, then compose actual production, quest and construction records when their transitions exist. Preserve old save decoding and replay exactly.** A separate new-world save path is the smallest safe delivery boundary until a real migration exists; it must be presented as a new world, never as an upgrade that secretly reset the existing one.

## Compatibility boundary

The database already stores bounded opaque canonical state, accepted batch, outcome and individual request/receipt bytes. Its two commit kinds are advancing step and held interaction; its four historical identity roles are commit cause, command, result and spawned entity. Gathering can use those same kinds and roles. No extra SQL tables, second service, IPC, generic event bus or schema-number bump is needed merely to add a versioned state component. Changing SQL object definitions, allowed kinds or physical bounds later would require explicit schema evolution because exact schema admission is enforced.

The current `WorldSnapshotCodecV1`, `WorldStepCodecV1`, `WorldActionCodecV1` and receipt v1 bytes are retained contracts. Their **replay behavior** matters as much as their fields: historical Give cannot begin awarding quest credit, constructing windbreaks or triggering rewards after a program update. Decoding an old genesis cannot install currently shipped gather nodes, tools or stock. Full recovery regenerates every historical after-hash and checkpoint, so even a seemingly harmless default field or changed action side effect can make old saves unreadable.

Use strict version-dispatch wrappers over the frozen codecs. Snapshot v2 contains a concrete gathering component and its rule/content pins. A null gathering component denotes the legacy profile; an empty-but-present component remains v2. The v1 encoder must reject a v2 object instead of silently dropping its new state. Batch v2 explicitly identifies the required profile, even for movement-only or action-free advancing batches, and admission requires exact agreement with the persisted snapshot. Old Speak/Give/Close commands can retain their action-v1 bytes within a v2 batch; a new Gather action gets its own explicitly versioned bytes. Receipt v1 can remain if its fields, result-ID/hash derivation, terminal semantics and rejection values remain unchanged.

Dispatch reads a bounded exact frame tag/version and chooses a known reader. It must not try one parser, catch corruption, and fall back to another. Unknown versions and mismatched profiles reject before simulation or writes. Existing v1 negative tests and independent golden fixtures stay unchanged.

Generic routing must include all current direct v1 call sites: snapshot/command `ContentHash` properties; `CreateNew` encode/decode admission; commit preparation and its stored per-command bytes; recovery genesis/batch decoding and regenerated checkpoints; `FindReceipt` exact request comparison; and `LocalWorldSession` pending-byte equality. Updating only the database entry point leaves retries, hashes or pending deduplication inconsistent. The session must select `state.ProfileVersion` when constructing every batch.

## Existing user saves and content

Keep the v1 source admission metadata and its pin intact. The existing client creates today's genesis before opening and checks its `AdmissionVersion`; replacing that one global pin would reject a previously valid world. Select the original supported admission when opening a legacy world, or retain a clearly named legacy entry point alongside the new save path. Never catch that mismatch and recreate the file. The current source identity derivation does not automatically make worlds with different admission versions distinct; a newly authored instance derivation/profile namespace should prevent accidental identity overlap between separately created worlds while preserving v1 identities exactly.

A future migration must acquire and fully recover the actual old save, retain its original exact history/receipts/occupied IDs, and record the old head plus new profile inputs. It must transform the current state, not the initial eight-wood genesis. A consistent SQLite backup/copy under ownership is required; copying a live main file without its WAL is unsafe. Publish the validated upgraded continuation atomically only after success. Do not invent a migration commit in one of the two existing gameplay kind slots just to avoid a deliberate migration design.

Source witnesses and new admitted meanings remain separate. The retained packet contains 49 records, but the first farm factory actively selected only Wren, farm, wood and quest. Gathering must explicitly admit the node/tool/source-implementation witnesses it uses. The source oak region is larger than the current loaded locality; clipping to a small authored accessible node set is a declared local adaptation, not restoration of every original spawned node or the full source placement algorithm.

## Gathering that survives replay

The source `World.Gathering.cs` implements **one paid swing**, rather than a single harvest at final depletion. Each swing spends 400 ATB, removes one node HP and yields `ToolPower`; oak starts with five hits, berry with four. The source range is 56 world units, or 448 subunits under the current ×8 mapping. Source oak/berry respawn delays are 900/700 simulation ticks at 20 Hz. These are simulation durations, not 900/700 calendar milliseconds. The old routine still damages a node when a full pack rejects the yield; correcting that behavior requires an explicit adaptation rather than claiming byte-for-byte source behavior.

Whether the new action performs a rate-limited swing or starts durable work must be declared before tests. A completed swing should atomically change node state, required eligibility/cost/cooldown, actual finite source/custody and receipt. A StartGather receipt instead acknowledges an admitted work record, not already delivered yield. Its progress, cancellation and later completion must be durable if that design is selected. Client animation, keyboard repeat and receipt lookup must not supply extra work or time. Accepted advancing steps alone advance work/respawn; reading holds, local pause and offline time contribute none.

`CountedAuthorityState` validates finite admitted source capacities and live, disjoint source intervals. It allows unused gaps; those gaps are **not proof that material was never issued**. Existing transfers conserve their live intervals, but the state has no retired/consumed-interval ledger. Gathering therefore needs an explicit persistent per-node generation/issued cursor or equivalent finite reservoir, coupled with admitted sources. Never reconstruct unused rights from whatever happens to remain in player inventory after a transfer or consumption. No refresh on scene reload, content reload or reopen may restore already issued stock.

Every gather node, tool/source/job identity must join the complete current/genesis index under its actual semantic role. Fresh lots, sources or jobs created later must be retained in the commit identity registry, including autonomous completion/regrowth with no new player action. The current action resolution returns only one spawned identity: if a transition creates multiple entities, its concrete result must report all of them. A currently depleted or removed entity cannot free its historical identity for reuse. Existing terrain source IDs remain distinct from inventory source families until actual coupled extraction is implemented; an oak resource node is not evidence of a mining right.

The host view can disclose the local node ID, display name, feet, node revision, required tool category and visible depletion/work phase for this sight-complete profile. It must not expose hidden issuance cursors, source allowances or other actors' inventory. Actor control, body function, current tool ownership, reach, node revision, cooldown/work eligibility and capacity are checked by the authority. The view supplies useful affordances, not permission to gather.

## Following crafting, Wren and construction

Do not make these later features artificial transfers from a stockpile that respawns its outputs. The original ration recipe is exactly two berries plus one wood producing two rations. The retained `MaterialRecipeDefinition` already provides pinned exact mass accounting and required work, but it does not execute crafting, assign output provenance or retire consumed input intervals. A concrete production execution must consume or reserve specific original intervals, retain their disposition, create bounded output/residue provenance tied to the execution and recipe pin, and commit that whole change atomically. Removing ingredients then attempting a refund loses provenance and can fail capacity checks; prepare a valid immutable candidate before writing.

Wren's retained quest requests six wood, names a windbreak in its offer/turn-in text, and declares 200 gil and 420 XP. The current handover proves none of those quest transitions. Introduce an explicit participant/quest state and committed eligibility/completion/reward disposition. An exact retry must return the old receipt without paying again, and ordinary gifts cannot infer quest acceptance or credit. Fund a monetary reward from an admitted account/source; 420 XP needs an explicit progression mapping. The windbreak must consume the same committed six-wood disposition, rather than letting those units fund both a structure and later crafting. Stage acceptance, delivery, work and completion only where actually required; do not invent an entire quest engine for one real retained example.

Construction adds actual persistent structures/terrain occupancy plus consumed materials and their cause. Drawing the old blocking tile alone is insufficient. Admission must prevent overlap with actor clearance, support violations and sealing the only playable approach; movement and interaction must use the newly committed collision state. The current canvas deliberately replaced 165 unsupported blocking props with grass. Reintroduce them only with their admitted structures. Pin the crafting/quest/build rules in the new profile so future recipe or reward balancing cannot reinterpret earlier commits.

## Required retained regressions

| Boundary | Minimal evidence |
| --- | --- |
| Legacy continuity | Open a retained schema-2/v1 save containing move/speak/give/close; compare exact head, historical receipts and occupied IDs. Continue a legal old-profile step and reopen. |
| Canonical compatibility | All v1 golden bytes and negative fixtures stay unchanged; v1 encoders reject v2 objects; strict dispatch rejects unknown version, malformed frame, stripped component and mismatched profile. |
| New world | New admission has explicit source/tool/node pins and bounded inventory capacity. Create, gather, close and fully replay the new save. Empty v2 state remains v2. |
| Request identity | Exact old/new request retries retain bytes and return the same receipt after restart. Reused ID with different version/payload conflicts. Unauthorized current delivery is rejected before receipt/private state disclosure. |
| Finite gathering | First/last hit, full pack, absent/wrong tool, body impairment, range/revision conflict, simultaneous contention, transfer after gathering, depletion, held/pause/offline freeze, and exact regeneration boundary. Restart before/after issuance never grants duplicate intervals. |
| Historical IDs | Source, node, lot and deterministic child collisions reject across current, genesis, earlier commits and sibling actions; completion without a client action still records every fresh identity. |
| Atomicity | Fault before/after commit, restart and retry: either all node/work/source/custody changes exist or none do. Corrupt a new component/checkpoint and require recovery failure before readiness. |
| Future transforms | Craft/build consuming the same interval twice rejects; exact reward retry never pays twice; partial progress and output-capacity failure preserve original rights. These tests are required when those operations actually land. |

The existing full-replay caps remain development constraints: 250,000 commits, 65,536 terminal outcomes and 128 MiB accepted journal bytes. Every nominal 20 Hz idle step is still committed, and every candidate serializes full state. Adding nodes/progress increases byte growth and hashing cost; measure one real gather/deplete/regrow trace and reopen, without claiming the 6,000-step synthetic fixture qualifies the new workload or a production save lifespan.

## Native-loop documentation corrections

The main native-loop README and world/authority contracts correctly distinguish walk/talk/give/save from gathering, crafting, quest completion and production qualification. The earlier architectural recommendation is already marked historical. The following present-tense wording should be corrected or explicitly superseded; this review edits no other document:

1. `content/CONTRACT.md`, final pending paragraph, still lists permitted client projection and atomically persisted movement/conversation/handover as pending. Those are now implemented for the bounded trusted local profile. Mark those specific entries realized and link to the integrated world/session evidence; remote authentication, general visibility, sound and accepted final art remain pending.
2. `content/CANVAS.md`, final paragraph, still says the coordinator must compile/import and inspect a native frame. Its author-time claim was accurate, but rendered/native evidence now exists. Append a dated link to `content/VISUAL_REVIEW.md` and `native-evidence/`, without rewriting the original worker evidence into a self-run pass.
3. `README.md` describes the handover as using “finite original source intervals.” The eight starting units are newly authored genesis stock, not imported legacy inventory. “Finite admitted genesis source intervals” is more precise.
4. Existing client-session review hashes and static closure statements are historical by design; the lifecycle results explicitly bind the final sources and close CS-01/CS-02 with native evidence. Preserve that record rather than recomputing its old binary hashes. CS-03 remains static/managed failure coverage, not native failure injection.

No broader architectural expansion is needed for the next gather-only slice. Its exit is a real finite, timed, tool-gated action that survives exact retry/restart and remains compatible with the original world profile; crafting, quest and construction retain explicit follow-up gates.

## Follow-up static inspection of the implementation

The coordinator subsequently added the strict snapshot/action/batch dispatchers, profile-2 codecs, gathering integration in the world processor/identity join, and native client action selection. This critic inspected those changes read-only while implementing the separately owned Hosting routing/projection. Two focused findings were reported and corrected by the coordinator:

| Finding | Correction verified by source inspection |
| --- | --- |
| Encoding v2 constructed a fresh gathering-null `WorldSnapshot` solely to obtain its v1 embedded basis, forcing a full terrain identity-index rebuild during every state encode. | A narrow internal `EncodeExplorationBasis` emits the exact retained component bytes from the already admitted root. Public v1 encoding still rejects a v2 object, and the v2 outer frame always includes gathering. This removes the identified redundant construction; workload performance still needs measured execution. |
| `FarmClientSession.OpenAsync` started `LocalWorldSession` before its new fallible oak/berry definition lookups. A failing lookup then disposed the authority directly but left the new unready background session running. | All fallible content/identity selection now precedes session construction. Ownership transfers only after those lookups succeed; startup failure still closes the untransferred authority. Native exception-path injection was not claimed. |

No other concrete defect was identified in that bounded static inspection. The known profile check applies to movement-only and held batches, command hashes use the exact version-dispatched request, historical source/child identities remain checked, and work advances only in the single advancing-step branch. Gathering after a dialogue opens is rejected through the current batch dialogue set; existing holds admit no work. Source code inspection is not a test pass: the author-owned Hosting tests and coordinator/worker core tests must execute against the final source before qualification.

The three requested native-loop documentation clarifications were applied as dated supersessions. The main record's 405-input statement now explicitly binds its earlier verified increment, rather than claiming those historical hashes still match a changing working tree. Old reports, source records and native evidence were preserved.
