# Independent terrain review

The reviewed local terrain implementation has **no blocking correctness finding** within its declared finite occupancy, excavation and reload scope. The documented limits match the code. This is a static review plus executed Python reproduction/arithmetic checks; this reviewer did not run .NET, Godot, persistence or gameplay tests.

Reviewed inputs are all ten `OpenFantasy.Core/Terrain` files, four terrain test files, the independent Python oracle and frozen fixture, and the terrain `CONTRACT.md`. [EVIDENCE.json](EVIDENCE.json) retains their exact SHA-256 hashes, along with the review script. The terrain owner confirmed these inputs were final when reviewed. This reviewer made no terrain application, test, oracle, fixture or contract edits.

## Findings by boundary

| Boundary | Review result and evidence |
|---|---|
| Signed XY lattice division | The C# adjustment converts truncating division/remainder into floor division with remainder 0–7. It is safe at `Int64.MinValue`: the quotient is already divided by eight before any decrement. Each lattice quotient plus one remains far inside Int64. The independent check compared this arithmetic with Python `divmod` at 10,515 signed values, including both extremes and negative lattice edges. |
| Interpolation and vertical range | Four nonnegative integer weights sum to 64. Relief samples are 0–16, so the weighted sum is at most 1,024 and fits Int32. Floor-once interpolation stays within ±relief. The independent check exercised 9,216 corner/weight/relief endpoint combinations. Rules prevalidate the maximum surface and minimum soil boundary, so the later `surface - soilDepth` subtraction cannot underflow for accepted rules. |
| Region extents and indexing | Inclusive maxima use checked offset arithmetic before access. Containment makes each index subtraction a small nonnegative offset even when the global minimum is near Int64 extremes. X varies fastest under Z/Y/X storage order. The review checked 49,176 index inverses across maximum positive/negative regions and a smaller asymmetric region. It did not multiply global cells into smaller signed subunits. |
| Seed, order and seams | Generation context binds world, realm, seed and exact rules hash. Region bounds, iteration history and branch are absent from relief/source derivation. Every column uses its global lattice corners, so horizontal region seams and independently requested vertical slices reuse the same initial substrate. Retained C# tests cover actual overlapping and vertically split regions; those tests were inspected, not executed by this reviewer. |
| Source and formation lineage | Formation IDs bind the original column/stratum; source IDs add original Z. Excavation retains both IDs and the exact material pin. The five frozen examples contain 76 nonvoid cells; their source IDs were consistent and unique among distinct sampled contexts/coordinates, and distinct from their own formation IDs. This is sample evidence, not a proof against hash collision. Code explicitly rejects only a detected source/own-formation collision; broader collision admission belongs to the inserting authority, as the contract states. |
| Branch copies | Omitting branch from generation context intentionally preserves initial source identity across branches. The complete region encoding still includes branch, so scoped hashes differ. This does not create export rights or establish a physical source budget. The contract correctly distinguishes source metadata from quantities and the future transit ledger. |
| Excavation | Revision, distinct in-region addresses, remaining solids and the 256-cell batch limit are checked before a candidate is returned. Existing snapshots and exposed cells remain immutable. Sorted persisted edit indices make request ordering irrelevant; separate batch counts intentionally change revision. Repeated depletion, invalid mixed batches and maximum revision fail instead of regrowing terrain or wrapping revision. Tests inspect complete depletion through 64 batches at maximum region size. |
| Standing and support | The query checks one-cell upright clearance and immediate full-cell support. It reports missing or unrepresentable below-cell dependencies as unavailable, not empty. It does not claim path reachability, multi-cell anatomy, load-bearing stability, atmosphere, hazards or fluids. Stacked tunnel tests use remaining natural strata, consistent with the contract's explicit lack of a placement/construction API. |
| Strict decoding | Top and nested frames require exact headers, versions, tags, field counts and scalar widths. Dimensions and rules validate before bounded baseline allocation; edit bytes are bounded by the actual region cell count, and indices must be ordered, unique and in range. Loading reapplies all edits and rejects original-void excavation or revision-zero edits. Nested and top trailing bytes reject. Maximum encoded depletion fits the 70,000-byte limit. |
| Persistence and history claims | Revision is not treated as a count of excavations or proof of a commit history. Nonzero revisions can roundtrip without a matching edit count, which the contract explains. Decoder restoration regenerates a bounded baseline only from its persisted inputs and reapplies every stored excavation. Selecting the correct current payload, preventing overlapping competing region authority and coupling mining consequences remain explicit store/transaction obligations. |

The public generation/edit APIs return consistent states through their controlled construction paths. Internal constructors are not exposed as a general untrusted-state admission API. Pinned material hash shape is validated, while actual catalog admission is explicitly deferred to the owner. No runtime generation setting comes from a mutable random stream or client rendering clock.

## Executed review checks

`PYTHONDONTWRITEBYTECODE=1 python3 Beta/implementation/p01/terrain-review/review_terrain.py` reproduced the independent terrain fixture exactly: **124,983 bytes**, SHA-256 `9b1dfeccc71642f0d96b50d41f5206e2880995f80ad85f0eee8a102a268c0074`. The artifact contains five examples, 154 expected cells, 13 canonical snapshot states and 29 malformed vectors. Snapshot/rules hashes and sampled source identities were independently checked from those retained bytes.

The script also executed the arithmetic checks above. It imports no C# runtime and cannot establish that the C# tests pass. The coordinator owns compiled test results. In particular, the 29 malformed vectors were inspected and retained here; their rejection by the C# decoder is not presented as this reviewer's executed evidence.

## Integration requirements retained

Before terrain becomes an authoritative mining action, the host still needs exact scope/content admission, current checkpoint/commit selection, a dependency resolver for region boundaries, coupled work/tool/occupant/support/fluid/custody effects and identity/source-budget registration. Generated cells must never be interpreted as free counted inventory, and generation must never replace lived terrain. Historical formation movement, macro geology, drainage, world-frontier quality and physical construction need their own representations and qualifications. These are existing explicit scope boundaries, not defects silently closed by this review.
