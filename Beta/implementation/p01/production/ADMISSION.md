# Production component admission

`ProductionFarmAdmission.CreateProduction(world)` prepares one empty, source-pinned production component for an existing gathered farm. It does not advance, regenerate, mutate or publish the supplied world. The coordinator owns the explicit copy-and-publish migration into profile three. A progressed world is valid input; its calendar, nodes, source cursors, tools, gathered items, residents and dialogues remain outside this constructor's mutations.

The exact embedded [production-farm/admission-v1.json](../../../Runtime/content/production-farm/admission-v1.json) is 5,439 bytes with SHA-256 `7419a27a9936c8157c98ab99537b2d4433b4d891a6ad9e61320346b551dfe7e1`, exposed as `ProductionFarmAdmission.AdmissionVersion`. It requires profile two and the retained gathering admission pin. The internal filesystem overload exercises the same bounded loader for tests. The existing resource glob includes this manifest in the Hosting assembly; no old manifest or source payload was changed.

Admission revalidates the complete retained original closure, original selected records and gathering manifest. It checks four source records for wood, berries, rations and `craft_rations` against their existing identities, canonical payload hashes and original JSON pointers. It then requires the actual current inventory sources to carry the unchanged wood and berry item pins. A new recipe, item or physical definition ID cannot alias any existing world identity or another new definition. New IDs use the stable `production-farm.definitions.v1` domain, independently of world seed.

The component begins at production revision zero with one recipe, no batches and no transformed lots. No output stock or independent sources are created. Its two existing input pins remain unchanged; its new rations/offcut item pins remain distinct from all four physical definition pins. The physical rule specifies one atomic operation, the original counts, 90,000 mg inputs, 80,000 mg packaged ration output and 10,000 mg wood waste. Per-unit allocation gives each ration 20,000 mg berries and 20,000 mg wood; the waste term receives 10,000 mg wood. [SOURCE_CONTRACT.md](SOURCE_CONTRACT.md) preserves the source/adaptation distinction and later use/metabolism obligations.

Input occupied volume is 160,000 µL and total output plus waste is 115,000 µL under the declared packing calibration. This admission is a recipe definition, not executable placement of a particular batch. The craft authority must validate combined raw/transformed count capacity, checked aggregate physical measures and exact consumed/product claims at execution. The supplied abstract tool units are not given speculative physical mass merely because the recipe exists.

The 14 authored admission cases cover a real progressed gathering trace left byte-identical, exact original input and independent physical pins, complete mass allocations, seed-stable definitions, embedded/filesystem equality, profile/admission mismatch, a structurally valid changed input pin, an existing place colliding with a new recipe ID, changed source/manifest files, and oversized/missing metadata. The coordinator owns their compilation and execution; test source existence is not a pass claim.

[verify_admission.py](verify_admission.py) is a read-only Python stdout oracle. It independently verifies all 51 frozen closure files, four selected records, existing input ID/version derivations, four complete physical definition encodings and both new item pins, then checks all allocation rows/columns and mass/volume totals. [ADMISSION_EVIDENCE.json](ADMISSION_EVIDENCE.json) records that executed data check and exact input hashes. This author did not run .NET or Godot. Final integrated results and any independent critic findings must be recorded separately.
