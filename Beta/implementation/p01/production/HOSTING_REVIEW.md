## Publication finding

**P2 — an absent destination main file is insufficient to establish an unused SQLite destination.** The initially reviewed `WorldProductionUpgrade.Publish` checked only `File.Exists(destination)` and `Directory.Exists(destination)`. If an orphan `destination-wal` already existed, publishing the verified main file beside it could cause SQLite to apply unrelated committed WAL pages when `OpenExisting` acquired the result. This could invalidate or replace the state that staging replay had just verified. Existing sidecars must be rejected and preserved, not silently deleted or interpreted as part of the new world.

**Closed after correction and regression qualification.** The owner introduced `SqliteFileSet.RequireUnused`, checking the main path and `-wal`, `-shm`, and `-journal` paths through file attributes so directories also reject. It runs at upgrade admission and after the `BeforePublish` fault seam immediately before the no-overwrite move. Shared new-world creation and backup creation use the same guard. Existing files and directories are preserved. This reviewer inspected the final helper, all four call sites and all 14 added regression cases; the owner's pinned targeted run passed 14/14 and the corrected full Hosting run passed 157/157. The final test also reproduces the unsafe control using the actual native SQLite **3.53.4**, then proves rejection preserves that same orphan WAL at the publication boundary.

[reproduce_orphan_wal.py](reproduce_orphan_wal.py) retained a separate, temporary-only Python SQLite experiment: a fully checkpointed candidate containing `verified candidate` was renamed beside an unrelated orphan WAL; opening the destination returned `unrelated stale WAL`. [ORPHAN_WAL_REPRODUCTION.json](ORPHAN_WAL_REPRODUCTION.json) records SQLite 3.53.1 and the observed 12,392-byte WAL. This demonstrates the substrate mechanism. It is not execution of the packaged C# adapter or its pinned SQLite library.

## Other reviewed boundaries

| Boundary | Static assessment |
| --- | --- |
| Source ownership | The original opens under an exclusive SQLite connection lease, is fully recovered before preparation, and remains leased through publication. A competing normal owner prevents upgrade. Migration runs against a private sibling staging database; the original journal is not transformed. |
| Consistent copy | `BackupDatabase` creates the copy from the leased SQLite connection. The staged head, usage, genesis, all journal bytes, command/receipt bytes, occupied identities and checkpoints are compared with the original. Copying only an active WAL main file is avoided. |

Metadata acceptance follows commit, with foreign-key enforcement restored in `finally`. |

| Publication uncertainty | No-overwrite move protects an existing main destination, and the final file-set guard rejects preexisting recovery sidecars. Failure before publication leaves no selected continuation; failure after publication may report an error although one complete continuation exists. The source and private diagnostic staging files are retained. |

The corrected **157/157** run retains those 21 cases plus all **14 sidecar cases**. The reviewer independently parsed [the final TRX](hosting-validation/test-results/production-hosting-debug-sidecars-final.trx), confirmed all 35 relevant cases passed, and checked the exact source hashes against the author's [SIDECAR_VALIDATION.json](hosting-validation/SIDECAR_VALIDATION.json). The initial 143-case evidence remains historical; it does not qualify the later guard. No pending runtime edits were reported when final review hashes were captured.

These interruption cases inject exceptions; they are not process-kill or power-loss migration tests. They do not prove filesystem directory-entry durability during abrupt hardware failure. The observed tiny-save timing in the retained test output is about 966 ms for 103 commits, not a production-scale migration or memory budget. The public API assumes an ordinary trusted local filesystem; hostile concurrent path replacement requires separate qualification. Pending private staging directories are deliberately retained for diagnosis, not selected or treated as new worlds.
