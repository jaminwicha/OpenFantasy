# Durable physical reservoir admission

Qualified 2026-09-19. This is a bounded P01 integration checkpoint, not a completed hydraulic
simulation, geological world or phase exit. [Summary](qualification/verification-summary.json).

## Implemented scope

Fresh profile eight admits an unplayed construction world and its exact complete reservoir owner.
The owner supplies the sole immutable watershed network; independent competing macro components
reject. Inventory and Production pins must match exactly. Reservoir IDs and calibrated definitions
join the world identity index, including body/terrain/quest roles absent from standalone composition.

Every material action reconciles against the latest accepted reservoir owner before its side effects
or spawned identities become accepted. Rejected gathering, crafting, transfers, quest delivery or
construction restore the action's entire candidate. Earlier accepted actions remain accepted. Ordinary
successors cannot drop the physical owner. Time passing beyond a forcing interval neither moves
water nor releases capacity or source reservations; empty/canceled ownership remains physical.

The explicit archive nests a genuine profile-five basis and unchanged full reservoir archive. Shared
inventory/Production appear in both formats and require exact equality; they are one authority. This
choice reuses retained interpreters and keeps old archives stable. The original 16 MiB complete-world
bound applies, including to individually valid larger standalone components. No size limit changed.
The existing schema-three writer, journal, command receipts, identity history and recovery own everything.

`--create-reservoir-world` accepts canonical inputs and a new database path. Existing inspection/step/
recorded-history operators report reservoir ownership. This is privileged offline admission, not a
network endpoint or an automatic upgrade. The default farm and presentation remain unchanged.

document check included living README in a historical manifest; frozen checking correctly scopes the
22 `spec-v1_1/` entries. The full failure index is in the summary.
