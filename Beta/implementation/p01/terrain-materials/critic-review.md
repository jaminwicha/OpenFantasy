# Bounded native critique

Reviewer: existing native `geography_admission_critic`; integration owner: central Astra task.
Read-only review; no reviewer edits, builds, tool-driven tests or human playtest claims.

The design review recommended a finite source allocation over full support, exclusive existing
counted custody, exact interior interval partitioning, actual remaining-stock demotion, protection and
reservation checks, accepted-cause identities with historical collision checks, complete-state pins,
bounded fragmentation and explicit separation from cross-branch transit authority.

The first source review found no concrete conservation or pinning defect. It identified missing
qualification for generated-ID collisions reached after cause validation; fragmented funding and
unrelated protected/reserved metadata; same-revision/different-hash plans and incompatible rebinds;
batch/active/lot limits; coordinate and physical overflow. These are retained as test gaps, not invented
runtime failures. The central task added focused cases covering them in `TerrainMaterialBoundaryTests`.

The follow-up reviewer response was: “No remaining consequential findings.” It confirmed that the
boundary tests address the listed gaps and the funded-material reference distinguishes standalone
planning from future live-world authority, retirement and allocation ownership. No broader simulation,
production feasibility, native rendering, full phase exit or human acceptance is inferred.

After that review the integration owner added the material-profile invariant that lot/storage
revisions cannot exceed the complete root. Direct Core tests and two real-host malformed archives
exercise this guard. It received local review, rather than being attributed to the earlier independent
source review. Readability edits do not change canonical bytes.
