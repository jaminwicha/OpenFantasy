# Finite construction and profile-five persistence

This increment connects the six units of wood actually delivered to Wren to one small, persistent, physically occupied seedling guard. It reuses the portable custody, material transformation, work/exposure, quest, actor, spatial and world-step authorities. A construction preview is an immutable candidate; only the existing hosted world transaction publishes work, material changes, geometry and receipts.

## Admitted meaning and physical accounting

The scale is the existing one metre per terrain cell, with 256 position subunits per cell. The retained wood item identity and source pin are unchanged. Its previously admitted physical calibration is 50,000 mg and 100,000 µL per unit. Six units therefore provide 300 g and 600 cm³ of wood.

The new authored assembly is a freestanding cross-slot guard. Its gross panel is 400 × 246 × 5 mm; each of two feet is 125 × 20 × 10 mm. Two panel notches remove a combined 1 cm³; two foot notches remove another 1 cm³. Ten disjoint integer-millimetre cuboids describe the final 540 cm³ assembly. The installed material weighs 270 g; three existing 10 g offcut units retain the other 30 g. Per-output material allocations bind those actual masses exactly. The offcuts' existing occupied volume is 25 mL each; occupied volume is not a conservation invariant or a storage-volume qualification.

`AuthoredJoineryBlankStock` explicitly admits an appropriate usable-stock interpretation. Original counted wood did not prove continuous planks, dimensions, grain or joinery quality. The source had no authentic slot-cutting tool, so this profile separately admits one finite authored Joinery Kit into Wren's actual primary inventory. It also adds one counted carrying allowance to that existing bag. Neither adjustment claims an original NPC possession or an additional physical bag.

`MillimetreBox` proves positive exact material volumes and nonoverlap. `ConstructionDefinition` requires the complete material volume and a connected positive-area face-contact graph reaching ground. Corner contact, edge contact and overlap caused by collision rounding cannot supply missing joints. The exact boxes become conservative half-open collision boxes by signed outward floor/ceiling at 256/1000 subunits per millimetre. This is a bounded supported freestanding assembly, not a general load, stress, stability, wind or structural-engineering solver. Its presence does not yet simulate weather protection or sapling survival benefits.

## Portable application types

- `ConstructionDefinition` pins the physical transform, exact item/physical allocations, usable-stock interpretation, actual tool qualification, member geometry, installed output index and finite experienced-work rule.
- `ConstructionProject` binds one owner/builder, the actual giver's completed delivery quest, its existing reserved custody, site/work positions, protected routes and immutable progress. `BuilderCarried` requires the project custody owner and builder to be the same actor. The reserved secondary bag travels with that actor; no fixed remote stock is invented.
- `ConstructionSnapshot` contains bounded definitions/projects and derives authoritative structures exclusively from completed projects. World admission joins every recipe, tool, quest, actor, custody, reservation, installed output and spatial structure. Each same-floor actor needs an explicit exit witness.
- `WorkConstructionIntent` supplies project/tool identities and expected revisions. It contains no client work amount, elapsed duration, reward or supplied material quantity.
- `ConstructionPlanner.Plan` consumes the current inventory, production, construction and spatial candidates. `ConstructionPlan` returns candidate components, public rejection and created identities; it performs no IO or publication.

The planner checks current actor control and project ownership before private stock/revision details. A living corporeal actor must retain Manipulation and ground locomotion, stand at the admitted work position, reach the site through the actual terrain/structure sightline and hold the exact unreserved, unprotected kit in its own primary bag. Wren remains the explicit source-derived Unassigned stat profile; no Farmer or Squire class is inferred for him. This rule is shared for actors regardless of human or host control. Encoded principal/session fields remain claims: the hosting boundary authenticates delivery before dispatch.

Each project requires the full exact completed delivery supply in its own reservation. The planner never temporarily removes that reservation to call ordinary crafting. No partial tools, output minting or invisible actor transfer stands in for a real source claim.

## Work, interruption and installation

The admitted rule is 200 work units at one unit per 1,800 experienced milliseconds. These are newly authored construction pacing values; the existing ration recipe remains instantaneous. Each eligible ordinary advancing-step command contributes exactly one work unit and retains an ordinary receipt. At the current 20 Hz host pacing this is ten nominal active host seconds and six experienced game minutes, excluding interruption, routing and waiting.

Held dialogue rejects work even if a caller supplies contradictory planning flags. Offline, paused and held periods create no construction time. Successful work suppresses that actor's movement in the same step. A selected advancing step still adds its one ordinary calendar/exposure increment when another action opens a dialogue. Partial earned work remains immutable and recoverable after interruptions; no elapsed wall time is synthesized on reload.

Every accepted work step checks prospective final placement using real body volumes, support, other structures and protected access routes. The route set includes both authored witnesses and each named actor's current feet to its admitted exit anchors. Obstructions postpone work; they do not move actors or discard material. Bounded route failure is a recoverable unavailable outcome.

Before the final step, all six raw units remain in reserved custody. Final success performs one atomic material transformation: retire every selected raw interval, retain a `ProductionBatch`, create the actual installed guard output and offcut output, reserve the guard, bind it to a completed project, and add its derived geometry. The batch is spawn ordinal 0, recipe output lots start at ordinal 1, and the structure follows all output ordinals. Current and historical occupied identities reject the candidate without consuming the last work unit or materials. Installed guard identity must remain its exact created output identity at revision zero; relocation, splitting and dismantling are not supported operations.

Persisted project revisions equal qualified work units. Per-builder total work must fit both the world's advancing-step count and that resident's actual experienced duration. A completed construction recipe batch must have exactly one matching completed project, and every spatial structure must match its exact installed member geometry. These checks prevent a decoder from admitting unsupported completion, substituting installed output identity, or inventing experienced work.

## Composition and compatibility

Ordinary `CraftIntent` rejects recipes bound to construction. `InstantCraftPlanner` and construction share the internal `MaterialTransformCommitter` for actual lineage accounting; the construction planner alone qualifies its reserved input rights and final installed-output reservation. The existing physical recipe's single required work unit denotes this final accounting operation, not timed assembly. Frozen recipe/material/production byte formats are unchanged.

Profile five deliberately adds `ConstructionSnapshot`. Its snapshot frame contains an exact profile-four basis with structures removed for that explicitly typed basis operation, followed by the construction state that reconstructs and validates every structure. The public old spatial/profile encoders reject nonempty unsupported structure state, so old formats cannot silently omit installed obstacles. Movement preserves structures, and later actions in a canonical batch receive the current spatial candidate so a newly installed object immediately affects collision and sightlines. The original world snapshot still owns the step's starting clock and actor state; no temporary partially committed world is manufactured between actions.

`WorldConstructionAdmission` contains only fresh construction metadata and new finite tool deltas. `WorldConstructionMigration` binds the exact profile-four head, world/branch, revision, advancing-step count and source/target admission pins. The target pin depends on the source admission pin and new admission, not on prior gameplay progress. The processor checks every new identity against current state and retained history, permits only explicit exact reuse of existing item/physical definitions, and appends the new construction recipe. It preserves previous lots, sources, cursors, transformations, quest/reward history, progression, clocks, residents, positions and dialogue.

Migration increments the world revision, custody revision and changed primary-bag revision; it increases that bag's counted capacity and admitted source budget by exactly one for the actual kit. It retains the production revision while adding newly admitted definitions. Fresh genesis has a separate qualified path retaining zero component revisions. No existing storage or source packet is serialized as replacement input in the migration request.

Work is bounded to 4,096 units per definition. These are explicit admission/backpressure limits, not permissions to truncate or drop accepted state. Existing production/custody/world bounds continue to apply.
