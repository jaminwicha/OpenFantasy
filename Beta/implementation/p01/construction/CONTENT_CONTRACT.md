# Construction farm content admission

`ConstructionFarmAdmission.CreateConstruction(WorldSnapshot profile4)` loads the embedded source closure and the new immutable construction manifest, verifies the existing farm's source admission, and returns a proposed `ConstructionFarmComponents` containing `Inventory`, `Production`, `Construction`, `Admission` and `AdmissionVersion`. The internal filesystem overload performs the same validation. Nothing is committed, moved, worked, paid or installed by this factory.

`Admission` contains only the new construction definitions/project and finite kit deltas. The root migration owns exact-head validation, historical identity collision checks, source preservation, replay and atomic publication. It must derive the retained inventory and production candidate from the current head. The convenience `Inventory` and `Production` values are reviewable candidates, not replacement serialized history.

The pinned manifest is [admission-v1.json](../../../Runtime/content/construction-farm/admission-v1.json), SHA-256 `6bce3173a4f5aadc1378cd69b687b74b9af54243221c33183299a686d0da6f0e`, 6,233 bytes. The loader permits at most16 KiB and validates the exact whole-file hash before parsing. It revalidates the existing quest and production manifests, full retained original source closure, and four additional source witnesses. Missing, oversized or changed data never substitutes defaults.

The profile validator reproduces the original **fresh admission metadata only**, including source Human Squire and fixed Unassigned Wren definitions, curve, original quest/reward, personal zero-balance wallets and finite200gil reserve, to recompute the accepted profile4 pin. It compares exact current definition versions and account identities while retaining current HP/MP, XP, balances, quest participation, time and material rights. The temporary initial metadata is never published or used to reset progress.

Definition IDs are stable across seeds under `construction-farm.definitions.v1`. World instances use a three-field OFC v1 scope frame containing `construction-farm.instance-scope`, world ID and branch ID, then `construction-farm.instances.v1` with explicit roles. Each new definition, work unit, project, source and lot is checked against the current complete world identity index and the other new roles. The publishing authority additionally checks historical identities.

The kit adds one raw source interval[0,1), one Wren-owned lot and one global counted source allowance. Wren's primary bag gains one counted carrying allowance; its revision and the custody revision each advance once for migration. Existing source intervals, lot revisions, reservation IDs, controls, policies, other bag capacities and production histories remain unchanged. The kit is not a new skill, stat bonus, species inference, physical bag-volume expansion or unlimited supply.

One construction definition reuses the exact old wood and offcut item/physical bindings, adding the authored installed guard item/material and construction-only recipe. The ten exact cuboids,270g installed output,three10g offcuts,200work units, carried project custody, correct source crop site and protected gate witnesses are detailed in [SOURCE_CONTRACT.md](SOURCE_CONTRACT.md). The constructor prepares a zero-work project even when a current actor obstructs its site. Actual work and installation must recheck those dependencies; content admission never moves the obstruction or installs free geometry.

`CreateGenesis(WorldSnapshot freshQuestGenesis)` is a separate fresh-only convenience. It rejects nonzero root/component revisions, elapsed or gathered work, produced lots/batches, quest participation, paid balances, noninitial stats, terrain edits, body injuries, changed initial time/positions or active dialogue. It calls the Core's fresh kit admission and creates a profile5 root with all initial counters still zero. It preserves the passed identity/terrain/persona/source pins. Existing saves use the explicit migration; this method is not a migration, restart, reset or conversion of progressed history.

The22 authored content test cases cover original-state immutability, full Wren bag preservation, exact input/output bindings and mass, both actual actor-body gates with Wren at work, occupied-site deferral, real paid quest preservation, fresh-root guards, embedded/filesystem parity, seed-stable definitions, source and role collisions, and changed/missing/oversized source inputs. **These tests were unexecuted when this contract was written.** The coordinator records actual build/test qualification separately.

The independent Python [verify_content.py](verify_content.py) emits [CONTENT_VALIDATION.json](CONTENT_VALIDATION.json) to stdout and validates source hashes, archive witness equivalence, source cells, material volume/mass, positive-area physical connectivity, outward collision rounding and two static full-body gate paths before/after the structure. It independently derives all eight definition IDs and three example instance IDs. This evidence does not claim C# execution, current occupancy, global route completeness or artistic approval.

The presentation artifact is a native13×8 declarative atlas region at [seedling_guard.tres](../../../Runtime/client/assets/construction-farm/seedling_guard.tres), with [provenance](../../../Runtime/client/assets/construction-farm/PROVENANCE.json). It is an unchanged original board motif used provisionally at the small panel's size. It omits feet, slots and animation; no new final art was generated. Artist acceptance, integrated audio, structural forces, tool wear and complete orchard protection remain pending.
