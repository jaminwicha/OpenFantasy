# Language profile restoration

`LanguageContractDecodingV1.DecodeProfile(ReadOnlySpan<byte>)` is the strict inverse of the unchanged `LanguageContractEncodingV1.EncodeProfile`. It restores one actor's exact revision, rules pin and up to 256 explicitly recorded language/register/mode entries. Each entry retains its full channel-definition pin and comprehension band.

Canonical ordering is language ID, register ID and communication mode. Duplicate or reordered channels reject, including a duplicate carrying a different pin or band. Communication modes are exactly Spoken/Signed/Written (1–3); comprehension bands are Unfamiliar through Nuanced (0–3). All identities retain their 16 bytes and hashes their full 32 bytes. An explicit Unfamiliar entry remains recorded; it is not dropped or equated with an absent entry in metadata.

The decoder checks strict framing versions, tags, field counts, lengths and enum values before returning concrete immutable profile state. It rejects unknown, malformed, truncated, oversized or trailing input with `FormatException`; no defaults, normalization, guessed language relationships or species/localization fallback are introduced. The encoded rules and definition hashes are restored exactly. Their presence is not proof of content admission: the host must select its accepted rules/channel definitions, and the existing `Query` continues to require matching subject/rules/recorded-definition pins before evaluating a requirement.

The exact maximum size is **47,280 bytes**, exposed as `MaximumProfileByteLength`. The fixed channel frame is 84 bytes, entry 180 bytes, 256-entry collection 47,150 bytes, and top profile framing/metadata adds 130 bytes. The decoder applies these nested bounds and maximum entry count before expanding fields. All existing valid profiles fit this exact bound, including UInt64 maximum revision. The upper-bound regression actually builds and restores all 256 entries and verifies exact encoded length.

Restoring receptive comprehension grants no bodily perception, expression, language learning, actor control or current action permission. The speaker needs separately established expression capability/knowledge and the listener needs the appropriate perception and receptive channel. The native loop's explicit Vocalization and Hearing checks remain independent. Signed, written and spoken entries never substitute for one another automatically.

Seven new C# tests compare all three existing independent profiles and eleven query expectations, verify the exact maximum, reject reordered/duplicate channels and malformed pins/modes/bands/nested frames, exercise every incomplete representative prefix and oversized input, and preserve explicit Unfamiliar metadata and immutable input ownership. The original language fixture, oracle, encoder and profile types remain unchanged. Worker Python verification and exact input hashes are retained in `EVIDENCE.json`; .NET execution and durable native-loop composition belong to the coordinator.
