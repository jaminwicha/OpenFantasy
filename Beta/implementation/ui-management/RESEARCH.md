# Interface reference research

Reviewed 2026-09-10. These are primary developer, publisher or platform sources. They support interaction principles, not a claim that another game's internals implement our deterministic simulation. Baldur's Gate, Assassin's Creed and Fallout are used as interface references rather than asserted to share a single genre or time policy.

| Source | Documented behavior | Design lesson and limit |
|---|---|---|
| [Larian: adapting Baldur's Gate 3 to DualSense](https://blog.playstation.com/2023/09/05/how-baldurs-gate-3-adapts-its-expansive-rpg-gameplay-for-your-dualsense-controller/) | Describes a system radial, customizable action/spell/item radials, adding/removing radials, direct Jump/Examine bindings and cursor mode. | Combine quick access with substantial full screens. Same capabilities can have device-appropriate presentation. Unlimited radial growth and stable slots are not proven by this article; our bounded favorites/stability policy is a separate design choice. |
| [Ubisoft: Assassin's Creed Valhalla accessibility](https://news.ubisoft.com/en-us/article/5Rys9UeXZh9bAjnHBZN4pC/assassins-creed-valhalla-bringing-accessibility-to-a-viking-epic) | Lists weapon-wheel toggle, alternatives to holds, two-step UI confirmation and adjustable interaction hold length. | Offer toggle/select/confirm and optional hold/release. Do not require simultaneous holds to use a quick menu. This is evidence about Valhalla, not every Assassin's Creed installment. |
| [Bethesda: Fallout 76 gameplay and accessibility settings](https://fallout.bethesda.net/en-US/news/fallout-76-gameplay-and-accessibility-settings-guide) | Describes analog navigation added to Favorites Wheel/Social Panel and digital navigation for other screens. | Cover analog and discrete navigation deliberately. The source supplies no optimal wheel capacity for our action catalog. |
| [Bethesda: using the Pip-Boy does not pause Fallout 76](https://help.bethesda.net/app/answers/detail/a_id/43397/~/why-am-i-being-attacked-while-accessing-my-pip-boy-2000-in-fallout-76%3F) | Players can be attacked while using that game's Pip-Boy. | A menu and a simulation pause are separate systems. Our UI must show our own agreed solo/shared/independent time policy; this is not a recommendation to adopt Fallout 76's danger policy. |
| [Sea of Thieves: support for radial menus](https://support.seaofthieves.com/articles/360026570874-Support-for-Radial-Menus) and [official 2.2.1 release notes](https://www.seaofthieves.com/es/release-notes/2.2.1) | Documents sticky/toggle radial alternatives and keyboard slots; release notes describe D-pad/arrow navigation around radials. | A wheel can preserve its visual form while providing non-analog operation. Eight slots is a shipped example, not an established optimum. |
| [Microsoft Xbox Accessibility Guideline 107: input](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/107) | Recommends analog/digital navigation, non-simultaneous operation, game-level remapping with updated prompts, and alternatives to sustained/repeated/chorded input. | Remapping alone is insufficient. The same actions need a usable list/discrete route, hold alternatives, cancellation and correct prompts. These are platform accessibility guidelines, not evidence our build passes them. |
| [Microsoft Xbox Accessibility Guideline 113: focus](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/113) | Focus should be visible; modal focus stays in the active dialog's controls. | Define one input owner and no fall-through actions. Restoring prior logical focus and consuming the opener's release are our concrete implementation choices consistent with this principle. |
| [Microsoft: progressive disclosure controls](https://learn.microsoft.com/en-us/windows/win32/uxguide/ctrl-progressive-disclosure-controls) | Describes essential defaults with optional detail and the discovery/stability risks of hiding controls. | Useful general support for relevant details and stable navigation. This is an older Windows desktop guide, not current game-specific layout advice or support for hiding essential warnings. |

The resulting [interface supplement](../PLAYER_INTERFACE_AND_NAVIGATION.md) proposes a bounded stable wheel, a complete browsable action library, capability-aware screen families and one atlas shell. Exact wedge counts, keys, menu artwork, latency and usability targets still require native comparison. Reference research does not establish that a large permutation catalog will be easy to use or cheap to produce.
