# Strict custody snapshot decoding

9 September 2026. This additive increment supplies the strict decoder deliberately left open in the [counted custody contract](../custody-contracts/CONTRACT.md). It preserves every prior v1 encoded byte and hash; it does not revise or replace the prior evidence report.

`CustodyEncodingV1.Decode` reads the existing tagged canonical frame. It bounds the entire payload before traversing it, then enforces exact field widths, tags, encoding version and record/collection counts. Custodian and lot identities must already be strictly sorted and unique. Constructor sorting is never used to normalize malformed wire input. All nested frames must end exactly; unexpected fields, trailing bytes, incomplete fields and unsafe declared lengths reject.

The exact maximum legal v1 size is **942,753 bytes**: 256 storage records at 78 bytes, and 4096 lots at 221 bytes with every reservation present, plus nested/outer headers and length prefixes. Storage collection maximum is 21,027; lot collection maximum is 921,631. These bounds derive from the existing schema and are exercised with a maximum-size snapshot. An identity is 16 bytes, a definition digest 32, an unsigned quantity/revision 8. A reservation is either absent (zero bytes) or a complete 16-byte identity; a present all-zero identity is not absence. Unknown protection bits reject before any enum narrowing can discard them.

After wire validation, construction revalidates complete-group local custody invariants: no unknown custodians, capacity overflow, duplicate item/storage IDs, overlapping claims or inconsistent definitions for one source. Such failures become typed `CustodyFormatException` diagnostics. No partially decoded snapshot is returned. Source existence, complete real storage contents, global claim budgets, authority, corruption recovery and supported schema migration remain adapter/world obligations.

The retained independent custody oracle is unchanged. A new stdout-only malformed-wire oracle derives 27 cases from those frozen independently specified frames, including unknown versions/tags, field/count/size limits, invalid widths, a large protection value that would alias if cast too soon, duplicates, unsorted records, invalid intervals, absent custodians, overlaps and over-capacity contents. Tests decode/re-encode both frozen snapshots, resume a further source-preserving transfer, check every incomplete original prefix, verify exact maximum size and optional identity semantics, and probe every single-bit mutation plus 1000 fixed-seed random frames. An accepted mutation must re-encode byte-identically; otherwise only the typed parsing failure is accepted.

The diagnostic host now supports `--inspect-custody <snapshot.bin>`. It enforces the same file limit before allocation and reports world/branch/revision/hash and counts under `snapshot-invariants` scope. Its output is not a durability, ownership or source-admission certificate. Existing host tests exercise positive projection, every malformed fixture and over-limit file handling. Executed results appear in the coordinator's [definition increment](../definition-increment/README.md).

This closes the v1 counted-snapshot byte decoder task. Atomic storage, restart of a real world, migration to future heterogeneous claims, whole-world identity admission and crash/retry receipts are still required before claiming durable custody. The previous counted-lot source restriction remains: crafted mixtures cannot be represented by inventing a fresh one-to-one source interval.
