## Hardware and instrumentation packet

For every run capture the host model, CPU/architecture/core count, RAM, storage device/filesystem/free space, OS build/power mode, editor checksum, SDK/TFM/published runtime, build flags/commit, dependency lock, seed/rules/package hashes, worker count, renderer and client counts. Name one actual measurement machine per supported desktop and identify the candidate minimum profile; an available developer machine is not automatically minimum hardware. Record Android/iOS portability/toolchain risks without claiming later mobile exports completed.

The coordinator must populate these hardware rows from actual machines. They are deliberately unfilled here. Do not report Windows or Linux pass results obtained only from compiling on macOS. Record CPU/core time, p50/p95/p99 step duration, queue length **and oldest due-work age**, work completed per category, allocation rate/GC pause, managed/native resident memory, database/checkpoint/event growth, load/replay/restore latency, networking/projection bytes and client frame time independently. Retain raw traces and stable run summaries. Use cold and warm runs and a no-renderer host comparison; do not bury durability stalls inside one average FPS.

The selected scheduler window is **50 ms**. The TDD also specifies initial 128 tactical actors/pocket, 512 detailed actors globally and sequential 64-evaluation fallback slices. These are current qualification parameters, not permission to drop coupled actors or claims of measured throughput. All other numeric budgets below are explicitly proposed fixture inputs/diagnostic thresholds, requiring named critic disposition before acceptance.

## LANG cases and candidate workloads

**LANG-01 — Meaningful population and due work.** Define separate profiles; do not treat their actor count as a cap. Candidate `actors-10000`: 10,000 realized actor incarnations total, distributed evenly across four progressing branch heads, with 128 detailed actors per head (512 total). Every persisted actor has applicable body/condition/needs/skills/class, possessions with custody, scoped knowledge, meaningful memories, motives, obligations, home/route and sparse directed relationships. A candidate seed generator gives each ordinary actor 12 actual owned lots, eight directed relations, 16 memories/evidence records, two competing goals and one feasible scheduled job; use different stable assignments and sparse optional state rather than duplicate empty records. These counts describe this fixture, not limits on character depth.

Candidate `city-20000`: 20,000 actual residents in one primary city's households/districts, plus three progressing branch heads with explicitly counted auxiliary populations. Propose 256 actors per auxiliary head, reporting **20,768 total incarnations** separately from **20,000 city residents**. Keep 512 detailed actors pooled across all heads; no multiplication of every city resident into four undocumented copies. Record resident/visitor/merchant populations, homes, routes, possessions, market/care/district jobs, vertical access, evacuation choices and complete dormant-state recovery. The coordinator may revise this distribution explicitly before recording baseline results.

For both, propose detailed cognition on deterministic one-exploration-second intervals and distant cognition staggered over 15 world minutes; recurring work/need/ecology events use their true applicable clocks. Record due transitions/decisions/expansions/commands per second, actual per-category completion and queued obligations. Stagger with identity-derived deterministic offsets, then inject a declared shared disturbance that makes 10% of inhabitants reconsider actual jobs. This is a repeatable burst scenario, not the default social tick. Actors without feasible work must preserve their blocked reason and next legal retry rather than silently disappearing from the workload. Candidate diagnostic: queue age returns to baseline within ten seconds of exploration progress after this finite burst; failure prompts analysis or an explicit benchmark revision, not dropped work.

**LANG-02 — Combined mutation and historical preparation.** Add real terrain/support/fluid edits, market/cargo transactions, encounter admission/merges and exact-history preparation concurrently as those services exist. Candidate initial ten-minute run: four controllers, each issuing one valid action per exploration second; one 256-cell terrain/support batch each five seconds; eight supported material/phase fronts in a bounded 32×32×8-cell space; four market transactions per second; one encounter-boundary merge and one exact non-checkpoint historical query per ten seconds. Use stable ordered commands, both accepted and intentionally conflicting reservations, and bounded burst variants. These are initial authored workload candidates, not promised player throughput. Report each service's actual work rather than counting a stubbed request as a completed feature. Compare p50/p95/p99 against 50 ms and diagnose oldest queued work. Preserve normal finite physical capacity at held encounter boundaries.

**LANG-03 — Sustained storage and memory.** Extend the same profiles, not a second fake simulator. Candidate endurance input is a 60-minute advancing session followed by repeated exact-history queries, unloading/reloading regions, restart and return to four heads. Record allocation/GC, resident memory, live objects, pending jobs, provenance fragmentation, checkpoint/event bytes and preparation/index size at fixed intervals. Include contemporary intervention, ecological dispersal and geological event-stage continuation. No arbitrary history deletion or post-load regeneration can improve the score. Host-only and native-client runs separate authority, persistence, rendering and collector costs. P00 must settle candidate absolute memory/storage/restore budgets using named hardware before these become pass gates; unknown values are not zero or already accepted.

**LANG-04 — Replay and export equivalence.** Same seed/packages/accepted input stream under one/two/four workers, debug/release, ARM64/x64 where available, supported desktop exports and standalone host. Crash before durable commit, after commit/before acknowledgement and during projection delivery. Retry identical and conflicting payloads, preserve ongoing jobs/queues/RNG and compare complete canonical state, receipt and event hashes. Include branch transit/custody, clock hold/release and source import payload identity. Differently timed human inputs are not expected to produce the same accepted ingress order. Debug/release equality alone does not establish cross-architecture or Godot export qualification.

Before broad P04 production, qualify these real cumulative workloads through Q-07. First address measured algorithms/layout/allocation/IO issues. Only a demonstrated remaining isolated hotspot or pervasive runtime/embedding problem justifies a bounded native kernel or whole Rust authority. A scalar microbenchmark is not that decision; do not create a speculative competing core.
