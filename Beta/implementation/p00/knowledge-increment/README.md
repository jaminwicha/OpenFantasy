## Implemented behavior

**Scoped resource knowledge.** A concrete projector checks the supplied current principal/session/world/branch/actor/control binding and publishes only that actor's acquired resource-count claims. Public packets preserve direct observation, report, belief, inference or dream basis, declared confidence and acquisition time. They omit private event provenance and global commit revisions. Changing only a hidden head or private cause leaves the public bytes and hash identical. Revoked/stale/foreign bindings reject with the same generic response. Cross-record aliases between private provenance and disclosed identities reject. These are exact supplied-state checks and redaction, not implemented authentication, perception or transport. See the [observation contract](../observation-contracts/CONTRACT.md).

**Language comprehension.** Immutable actor profiles compare exact language/register/mode prerequisites under pinned definitions/rules. Spoken, signed, written and cant channels remain separate; absent channels are unfamiliar. Another party member's skill, a culture label or localized text grants nothing. Three authored profiles and eleven query examples demonstrate the intended boundary. Band comparison neither translates speech nor establishes truth, permission or acquired knowledge. See the [language contract](../language-contracts/CONTRACT.md).

**Source field accountability.** The [first-loop mapping](../first-loop-mapping/README.md) preserves six primary records, two gathering context records and two code-defined resource archetypes. All **74 JSON field rows** (66 scalar leaves and eight containers), **28 dependency edges**, **14 supporting endpoints** and four witnessed missing-field defaults are checked. Seven original key/count fields have lossless representations in existing contracts; 48 fields still require explicit transforms/gameplay and 19 remain retained source-only. No whole record is labeled admitted or playable.

Actual source behavior now has explicit conversion decisions: Wren's six-wood quest does not construct its promised windbreak; gathering yields per swing and uses depletion HP rather than material hardness; old tick/coordinate units need declared embeddings; and the ration recipe supplies no mass/work/waste calibration. The same wood cannot satisfy both a completed quest and consumed recipe inputs. These findings guide connected implementation without rewriting or losing original content.
