# OpenFantasy runtime

This is the retained development runtime: a portable C# core, shared durable hosting library, headless executable, Godot C# client and executable tests. The native farm now connects player/NPC movement, Wren's original opening dialogue, a finite six-wood handover and save/reopen through one authoritative world. Terrain, bodies, language, custody, dialogue and time persist together. The gathering profile additionally admits real source tools, finite oak/berry reserves, earned effort, depletion and advancing-step regrowth. The production profile turns actual ingredients into rations and recoverable offcuts, retains consumed raw/derived rights, and upgrades an existing gathered save on a verified copy. Quest/construction completion, food use, Wait combat and multiplayer remain pending. The [increment record](../implementation/p01/native-loop/WORLD_CONTRACT.md) and [preparation packet](../implementation/p00/README.md) distinguish measured behavior from full phase exits.

## Build and verify

Use Python 3, the exact .NET SDK in `global.json`, and the .NET edition of Godot pinned in `toolchain.json`. The SDK executable must have access to the required managed runtimes. A standard non-.NET Godot editor cannot run this project.

From this directory:

```sh
python3 tools/verify.py --dotnet /absolute/path/to/dotnet --godot /absolute/path/to/Godot
```

The verifier checks the actual tool versions, independently regenerates all retained independent numeric, command, package, custody, scheduling, history, exposure, anatomy, production, observation, language, authority and terrain fixtures, restores locked dependencies, builds Debug, requires every discovered core and hosting test to execute and pass, exercises host contract inspection against valid/malformed inputs and retained source-packet hashes, imports the client, and runs a headless Godot smoke check. It compares host/client primitive results and records the managed runtime observed inside each process. It also kills the dedicated host before/after an actual SQLite commit, reopens and retries without duplication, refuses a competing process, and checks matching durable results and actual native SQLite settings inside Godot. The native farm probe also routes movement, talk, give and close through the real client and compares the paused public view after process restart. A zero process exit does not excuse missing tests or Godot error output. Results and raw process output appear in `artifacts/verification.json`, with a fresh TRX report for each run. Optional `--forbidden-token TEXT` checks text input contents and all input paths for a prohibited name; binary assets are hashed and reported separately; the report states whether that scan was requested. This remains local binding evidence, not a performance, rendering, networking or desktop-export qualification.

The portable test suite can run independently:

```sh
dotnet restore tests/OpenFantasy.Core.Tests/OpenFantasy.Core.Tests.csproj --locked-mode
dotnet test tests/OpenFantasy.Core.Tests/OpenFantasy.Core.Tests.csproj --no-restore
```

To open the farm, build Debug and open `client/project.godot` with the pinned .NET editor. Put the selected SDK directory on PATH and set DOTNET_ROOT to its runtime root before launching the editor; both matter for editor SDK discovery and native runtime selection. The current source-based visuals are a provisional original-asset baseline, not the approved production art target. Move with WASD/arrows or the left stick; E/controller A talks or closes your conversation, G/controller X hands over up to six wood from one counted lot, F/controller Y gathers from a nearby plant with its required owned tool, C/controller B packs two berries and one wood into two rations plus one wood offcut, and Esc/Start pauses. Closing saves through the host; reopening retains the world. The default local save is `user://worlds/wrens-farm-production.sqlite`. When that file is absent and `user://worlds/wrens-farm-work.sqlite` exists, startup explicitly upgrades a verified copy of the gathered world and retains its original file and complete history. A failed or unsupported upgrade stops opening; it never resets the world. A new game admits production directly. The earlier exploration world remains at `user://worlds/wrens-farm.sqlite` and can still be opened with `--legacy-farm`.

`tools/check_native_farm.py` exercises those actual Godot input/view adapters and reopens the same durable world in a second process. Its default is headless; `--rendered` also retains native screenshots for a separate visual review. This proves the small walk/talk/give connection, not Wren's complete quest or the full first-prototype loop. `tools/check_native_gathering.py` exercises real gather input, finite yields, a paused resource, exact process recovery and subsequent regrowth; its rendered option retains source-asset screenshots. `tools/check_native_production.py` runs three actual native processes: gather berries under the retained rules, upgrade the saved world and craft, then reopen and gather/craft again. It checks that the old save bytes remain unchanged, outputs survive restart, and paused projection fields remain exact. All three probes run from the integrated verifier.

## Project boundaries

- `src/OpenFantasy.Core`: portable deterministic primitives, immutable command/receipt contracts, pinned package metadata, finite counted custody candidates, calendar queues and exact historical request boundaries, anatomy/condition definitions, material recipe validation, exact input retirement and transformed-output entitlements, experienced-time arithmetic, scoped resource-knowledge projection and actor-owned comprehension profiles, finite source/control admission and seeded stacked terrain with retained excavation. It has no engine or third-party package dependency. See its [byte and arithmetic contract](src/OpenFantasy.Core/CONTRACTS.md).
- `src/OpenFantasy.Hosting`: shared net8.0 SQLite adapter, durable counted and composed-world streams, identity history, strict journal recovery, embedded source-pinned farm admission and the serialized local session. Its 20 Hz clock has no input-driven acceleration or catch-up debt. It has no Godot dependency or IPC layer.
- `src/OpenFantasy.Host`: the retained headless entry point. `--inspect-foundation` exercises the same core. `--inspect-command <command.bin>` validates a bounded canonical envelope, `--inspect-package <manifest.json> <payload-file>` validates metadata and payload bytes, and `--inspect-custody <snapshot.bin>` checks counted snapshot invariants. Those inspection diagnostics issue no gameplay receipts. Local world operations below run the real durable counted authority; network authentication, session grants and gameplay projections remain pending.
- `client`: the independent Godot project and C# presentation adapter. Godot owns rendering, not authoritative outcomes.
- `tests/OpenFantasy.Core.Tests`: independently generated reference vectors and behavior/edge tests.
- `tests/OpenFantasy.Hosting.Tests`: actual temporary SQLite worlds, player/NPC transfers, concurrency, restart, corruption and independent critic regressions.
- `content`: the retained source dependency packet and versioned farm admission. The full source closure is embedded byte-for-byte for runtime use without a source checkout. Wren, the farm locality, finite wood and opening utterance now have admitted behavior; the remainder of the preserved packet still requires coupled conversion.
- `tools`: reproducible local verification. Build artifacts stay untracked.

Only the client references the engine. The solution's Debug configuration builds all development artifacts. Release maps the client to Godot's **ExportRelease** and the ordinary .NET projects to Release. Building either configuration does not create a distributable Godot export; actual templates, export presets and supported-device execution remain required. In particular, a macOS build does not establish Windows/Linux support.

## Candidate toolchain and portability

The current SDK is 10.0.401. Core, Hosting, tests and client target net8.0; the headless entry point targets net10.0. These are distinct from the managed runtime Godot actually loads. The local candidate installation contains runtimes 8.0.31 and 10.0.12, and the smoke report records which was selected. Godot.NET.Sdk is pinned to 4.6.0 with locked NuGet dependencies. Desktop framework/export selection must be qualified in P01; net8.0's approaching support end makes that an early decision, not a production support promise.

`toolchain.json` retains verified official download metadata for the initial macOS ARM64 machine and candidate export templates. Install tools side by side. When adding an older runtime to a newer SDK directory, retain the SDK's root launcher and copy only the runtime's versioned `shared/Microsoft.NETCore.App` and `host/fxr` directories. Download checksums prove archive identity; actual builds/runs prove only their recorded exercised paths. Other OS/architecture packages and mobile workloads require their own qualification.

Names, persisted tags and namespaces are stable product/domain identifiers. Temporary planning names do not belong in code or project metadata. Keep future domain models in a few clear assemblies; do not generate an assembly or empty interface for each design concept.

## Local durable authority

These commands require local operator access to a database and canonical accepted input files. Principal/session arguments describe that operator's trusted local delivery context; they do not authenticate remote clients.

```sh
dotnet run --project src/OpenFantasy.Host -- --create-world /absolute/world.sqlite /absolute/genesis.bin
dotnet run --project src/OpenFantasy.Host -- --execute-local-command /absolute/world.sqlite /absolute/command.bin PRINCIPAL_ID SESSION_ID
dotnet run --project src/OpenFantasy.Host -- --inspect-world /absolute/world.sqlite
```

Creation refuses every existing file. Open rejects unknown/modified schema, corrupt snapshots, discontinuous or unreproducible command journals and incomplete historical identity reservations. Each fresh valid delivery atomically records its command, receipt, resulting state and reserved IDs before returning a receipt. Rejected gameplay decisions consume a commit sequence while leaving custody revision unchanged. Exact retries return the original result; changed content under the same key refuses. IO or uncertain commit failures require closing/reopening and retrying the exact command.

The pinned SQLite adapter uses Microsoft.Data.Sqlite.Core10.0.12, SQLitePCLRaw.bundle_e_sqlite3 3.0.5 and native SQLite3.53.4. Verify actual `sqlite_version()`/`sqlite_source_id()` on every supported exported target. The above CLI commands retain counted schema version1. The exploration/gathering farm retains composed schema version2. Production uses composed schema version3 with an explicit typed migration row; earlier genesis, journal rows, receipt keys and identities remain byte-identical in the copied continuation. It journals compact step/outcome records, maintains one current head and stores checkpoints every 6,000 advancing steps or 10,000 commits. Full replay validates checkpoints, receipts and identities before readiness. Development recovery limits are 250,000 commits, 65,536 action outcomes and 128 MiB accepted journal bytes; reaching a limit stops the session visibly and retains the save. The bounded profile2-to-profile3 copy-and-publish migration is implemented. Long-lived checkpoint-tail recovery, broader schema evolution, scheduled work, outbox, control rebinding and network sessions remain production obligations. The current production ledger admits 32 recipes, 256 retained operations and 4,096 combined live lots; these are development bounds, not a long-lived economy capacity promise. Storage remains count-limited; calibrated mass allocation does not establish a physical volume-capacity system. Profile3 uses a global production revision token, so independent simultaneous crafts can conflict; fair multi-actor crafting needs explicit later-profile qualification before the 1–4-player claim. The local session performs synchronous database work on its serialized worker, never a Godot frame callback.
