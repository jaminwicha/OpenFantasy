# Local session contract

`LocalWorldSession` takes ownership of a successfully admitted `SqliteWorldAuthority` and one current player control binding. Construction does not start game time: `SetReady(true)` enables selection. The current adapter is a trusted local-host profile, not network authentication. The authority must not be independently mutated or disposed after ownership transfers.

The host selects at nominal 50 ms monotonic deadlines. Late deadlines are discarded and the next deadline starts at least 50 ms after a stalled step finishes; there is no catch-up or offline simulation. Movement is one exact 32-subunit cardinal sample, or zero to stop, with a 150 ms freshness lease. Inputs never choose simulation elapsed time. Losing readiness clears movement. A step already selected at the cutoff may finish committing after readiness changes; later steps remain paused.

One player action can be pending. Identical bytes share its outcome, a different new request is explicitly refused while it is pending, and an exact durable retry can retrieve its previous receipt. Current delivery and actor control are checked before receipt access. Pending input is neither a receipt nor a durable acknowledgement. The task completes with a gameplay receipt only after `Commit` returns; stopping cancels pending input. A closed or failing backend faults `Completion` and pending work.

Current and historical occupied command identities are rejected before selection. A private preview catches further command/result/spawn selection conflicts. Such a request faults with `AuthorityDispatchException`; an ordinary step is rebuilt with a fresh host cause and the other selected movement. Held interactions have no empty fallback commit. Storage/IO failures and `WorldRecoveryLimitException` stop and fault the session; they are never converted into gameplay receipts or hidden by idle fallback.

An advancing step resolves actions first. If an action opens a dialogue, that already-selected step still contributes one ordinary calendar/exposure increment while movement is suppressed. A held batch selects actions only and contributes no clock time, including the close that releases the final hold.

`LocalNpcController.PolicyVersion` is `local.home-amble.v1`, a newly authored implementation policy. SHA-256 input is that exact ASCII domain followed by fixed-width world ID, actor ID and unsigned cycle ordinal. Each 64-step cycle admits up to 16 movement samples followed by 48 idle steps; the direction is the digest's first byte modulo four. Proposed feet remain within the exact XY home-radius circle. Current actor bindings, full body clearance, support and occupied space are still adjudicated by the same world processor used for player movement. This is finite home amble, not a claim that the original NPC's psychology or schedules have been migrated. The source version and implementation hashes belong to the coordinated build evidence. Changing the policy for ongoing worlds requires future explicit compatibility/migration rules.

Accepted movement samples are journaled. Recovery replays those samples rather than rerunning the NPC controller. Rendering supplies no NPC decisions or world truth.

`LocalWorldView` is an immutable cached projection. This admitted local profile is sight-complete; its actors' names, positions, presence revisions and controller kinds are visible. Only the selected player's own counted lots and storage revision/quantity, and their addressed active dialogue, are included. NPC inventories, source claims, commit sequence, state hashes and storage diagnostics are excluded. This is a bounded local projection, not the future world's global knowledge/visibility system. No currency, food consumption, injury healing, quest credit or exposure-driven aging is invented here.

The internal `TimeProvider` constructor is the monotonic host-clock seam used for controlled pacing and input-lease tests. It changes host scheduling only and never supplies game time to the core.
