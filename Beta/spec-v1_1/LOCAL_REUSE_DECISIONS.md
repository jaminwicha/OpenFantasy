# Local implementation reuse decisions

## Decision and evidence boundary

Retain Beta's new portable deterministic C# authority and Godot C# presentation. Fully incorporate Alpha OpenFantasy's content and selectively adapt its algorithms and tests. Extend RogueFiction's contextual character, quest and narrative ideas through Beta's shared actors, knowledge and history. The additional local games supply useful bounded algorithms, failure cases and tooling patterns; none supplies the combined authoritative foundation required here.

The [lifeform audit](../research-v0_9/local-lifeform-code-review.md) and [terrain/roguelike audit](../research-v0_9/local-terrain-and-roguelike-code-review.md) inspect actual implementations, manifests and test source. Their source fingerprints distinguish an inspected candidate from a project name or README promise. The earlier [lineage review](../architecture-decision-review-2026-09-08.md) and [place/progression research](../research-v0_8/places-puzzles-and-progression.md) remain applicable to Alpha, RogueFiction, PacRogue and roguelinks. This decision does not authorize silently importing another runtime's persistence, random-number or scene ownership.

Only one additional local executable check ran: LifeFormzFable's `persistence::tests::loaded_game_has_identical_future_continuation`, using its locked offline dependencies and an isolated temporary target directory. It passed one test with 88 filtered out, comparing continuation through 40 post-load ticks. That is evidence for this source behavior on the recorded environment, not for the full source suite, Beta adaptation, cross-platform identity, performance or playability. All LIFE-V and LOCAL qualification cases below remain unrun. No source was extracted or changed in these audited projects.

## Retain failure cases and testing techniques

VirginiaCreepers' `SeasonalReplayProbe` compares 30/60/144 FPS, jitter/hitches and reduced motion using sorted authoritative fields. Adapt that metamorphic comparison to Beta's canonical state, detailed/coarse execution, saves and branches. Its `HabitatLifetimeProbe` distinguishes duplicate credit, different organisms at one position, maturation identity, reset isolation and garbage collection. Keep these scenarios while replacing weak object-reference receipts with durable source/cycle/interaction/receipt identities. A saved historical flower must not pay twice because it became a new managed object on load. Durable history does not require retaining all scene objects.

LifeFormzFable's continuation fixture is a useful starting pattern for save/restore differential tests. Expand it to crash boundaries, exact requested history, source claims, actor learning, target validity and queued work, with independently enumerated state rather than a convenience hash omitting important fields. Its single SplitMix/modulo stream and same-process determinism checks do not establish Beta's order-independent addressed randomness or desktop parity.

SRW's native adapter demonstrates an opaque Rust handle behind in-process C# P/Invoke. It is concrete evidence that Rust need not imply IPC. The review did not audit the native implementation or qualify its exports/performance, so it cannot close Beta's C# versus Rust gate. Do not inherit its sector-regeneration save model or parent-consuming RNG forks as Beta defaults. LANG-01–04 remains the comparative decision path with actual geological, ecological, actor, archive and network workloads.

## Rejected foundations and misleading matches

Lifeformz1 offers phase-separation examples, but global `Math.random` replacement and a collision guard lost when cells are recreated make its runtime unsuitable. The small Python Lifeformz prototype lacks the resource accounting required for reproduction and uses color as hostility; its simplifications are not Beta ecology. Lifeformz2 has no comparable implemented source in the inspected area. RustAdventure's sampled terrain generation lacks the coherent seeded connected world required here. Cryptbro is a Go financial-trading application and has no relevant crypt/dungeon implementation. These are exclusions based on inspected scope, not claims about all possible future versions.

Do not adopt an implementation merely because it is already Rust, C#, procedural or labeled a simulation. Beta's exact history, live interventions, resource ownership, broad actor depth and user-facing quality are the acceptance contract.

## Extraction workflow and completion

At P00, enter each selected candidate into the production inventory with source path/hash, authorship/license or ownership evidence, dependencies, intended benefit and a bounded destination module. Recheck drifting source revisions before extraction; retained audit hashes identify evidence rather than permission to overwrite another project's newer work. P01–P03 introduce the highest-risk candidate fixtures before dependent production. Adapt only the needed mechanism and tests behind Beta's existing interfaces. Preserve attribution and mappings for actual imported code/assets; do not import unrelated project infrastructure.

Record whether a candidate was adapted, used only as a reference, or rejected after a failed proof. Run the independently retained cases against the actual Beta build and supported profiles. P04–P10 expand the same services; P11 closes the selected reuse inventory and its provenance/behavior obligations; P12–P14 retain full-game and platform regression. A rejected optional candidate is complete when its useful lesson or reason is recorded and the required Beta behavior has a supported alternative. Rejection never removes a required gameplay feature.

The ten LIFE-V/LOCAL cases augment existing LANG, PLACE, ECOG, LEARN and migration fixtures. Reuse the same harness and seeds where appropriate while keeping distinct assertions. Source test availability, one passing source test, deterministic output and a visually appealing source project are separate evidence levels. None closes Beta's production acceptance on its own.
