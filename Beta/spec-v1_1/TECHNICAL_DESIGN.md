# Beta technical design

## 1. Authority, scope and implementation baseline

This is the implementation contract for the [requirements baseline](REQUIREMENTS.json), read with [GDD](GDD.md), [decisions](DECISIONS.md), the production plan and validation register. Revision 1.1 supersedes the current authority of specification 1.0, which remains preserved. It retains existing decisions and adds explicit geological, fluid, ecological, audio and procedural-introduction contracts. Required tests are not completed evidence. The destination includes complete content migration, autonomous society, deep production, history, multiple grand arcs, temporal play and production release; an early slice does not replace that destination.

Build one engine-independent C# authority with Godot presentation and platform adapters. Rebuild state ownership in Beta, import all legacy content, and selectively retain verified algorithms/fixtures; do not extend the original monolithic world or movement-mode vehicle model. Use logical modules in one process. Solo embeds the same host used by co-op; dedicated hosting uses the same portable core in a plain .NET executable. No gameplay authority resides in Godot nodes, animation callbacks, a language-model response, SQLite triggers or remote services. No Rust/C++ kernel, IPC bridge or microservice partition is selected.

The owner's expanded-scope C#/Rust reassessment is recorded in [core language research](../research-v0_8/csharp-rust-core-reassessment.md). C# remains selected, with a P00–P03 qualification gate before broad P04 production: retain language-neutral numeric/RNG/command/archive fixtures, measure complete workloads, allocation/GC, durability, backlog and exported behavior, and distinguish algorithmic/storage costs from language costs. A whole Rust authority behind coarse in-process C ABI operations is a valid alternative that does not require IPC; it would replace core ownership, not add a second world or remove the Godot C# client's platform constraints. Choose it only through the recorded gate if pervasive measured managed-memory/latency or concrete embedding needs justify the integration and it passes parity/export/recovery evidence. A demonstrated isolated hotspot may instead justify one bounded native kernel. Do not implement two complete cores speculatively. Required evidence is not yet executed, and the current selection is not a performance guarantee.

Launch supports Windows, macOS and Linux, one to four simultaneous players per hosted world. Android/iOS are a later supported production phase using the same core. P00–P01 qualify a deliberately selected Godot 4.6 .NET stable release with .NET 10 LTS: P00 pins exact candidate editor, SDK, target framework, export-template and dependency versions/checksums in Beta; P01 accepts the pair only after exporting and executing a retained slice on all three desktops. Do not silently reuse or upgrade the original game's Godot.NET.Sdk 4.4.1/net8 pin. Godot documents desktop C# support; its 4.6 basics recommend a current stable SDK and require .NET 8 or later. That does not substitute for validating this precise pair. Microsoft lists .NET 8/9 support ending November 2026 and .NET 10 in November 2028.[^1][^2]

P00 creates explicit Beta project include paths and excludes Beta source from the original project's compile/import scope. Shared abstractions belong in the real core from their first fixture. Tests, importers, schema migrations and diagnostic tools are retained. Refactoring remains permissible when evidence shows a defect.

## 2. Modules, public operations and persisted ownership

Only the authority applies mutation plans. Modules expose typed commands/queries; they never mutate another owner's fields through callbacks. A commit may atomically cover several modules. Initially these responsibilities can be folders within a few assemblies rather than one assembly per row.

| Module | Canonical state | Public contract |
|---|---|---|
| Authority | IDs, versions, command receipts, sequence, scheduler, RNG counters | `Submit`, `Validate`, `Plan`, `Commit`, `Explain` |
| World/history | 3D topology, materials, support/fluid dependencies, calendar, geological features/processes, reservoirs, ecology/cohorts, epochs, lineages and cosmology | `PrepareMacroRegion`, `QueryFeatureAt`, `AdvanceGeoStage`, `AdvanceEcology`, `GenerateCell`, `Excavate`, `Construct`, `AdvanceDomain`, `ApplyExposure`, `ForkCheckpoint` |
| Actors/rules | Body/lifecycle, attributes, needs, conditions, skills, classes, learned powers, controller permissions | `EvaluateAction`, `Learn`, `ApplyEffect`, `ChangeController`, `ResolveBirth/Death`, `TransitionForm`, `InterpretExpression` |
| Society/cognition | Directed relations, evidence, beliefs, goals, commitments, households, parties | `Observe`, `PlanAction`, `Recruit`, `CommitJointAction` |
| Production/custody | Material lots, items, part condition, assembly topology, ownership, jobs and reservations | `ReserveInputs`, `Work`, `Transform`, `Fit`, `Repair`, `Transfer` |
| Travel | Routes, motion, boarding/towing/mount links, crew roles and local frames | `Move`, `Board`, `Mount`, `AssignCrew`, `Transit` |
| Institutions | Membership, office/hierarchy, mandates, law, estates, treaties, supply orders, territorial outcomes | `Negotiate`, `IssueOrder`, `ResolveClaim`, `ResolveSuccession` |
| Narrative | Arc/adventurelet/deck instances, participant bindings, eligibility, choices and continuations | `DrawOpportunity`, `BindRoles`, `AdvanceArc`, `RequestScene` |
| Encounters | Membership, tactical time, readiness, held decisions, coupled dependencies, exits | `Admit`, `CommitAction`, `Merge`, `RequestExit` |
| Adapters | Durable bytes, network delivery and presentation caches | `Load/StoreCommit`, `Deliver`, `Project`, `Render` |

`EntityId` is a canonical 128-bit identifier. Generated IDs derive from SHA-256 over world seed, generator version, stable source address, entity role and ordinal; live-created IDs derive from the accepted command/event ID and spawn ordinal. Use the first 128 bits and reject any detected collision. Compare canonical big-endian bytes, never runtime hash order. Distinguish definition ID/version, ancestry ID, branch incarnation and live instance. Inventory, party, crew and quest records reference identities; none embeds a second mutable copy.

Definition IDs use package namespace plus stable key and version hash. Definitions are immutable after acceptance. Instances store actual state and explicit overrides. Derived caches are rebuildable; personal knowledge, job progress, damage, promises, receipts and mutations are not caches.

## 3. Numeric, random and ordering contracts

Authoritative X/Y/Z coordinates are signed 64-bit integers at 1/256 cell units; the initial physical profile defines one cell as one metre. Realm identity is a separate coordinate, never an elevation value. Heights and body dimensions use these integer subunits; material quantities use typed integer units, such as milligrams and microlitres. Do not mix quantities because their integer types match. Body clearance and navigation use deterministic integer geometry. Godot float physics may assist presentation, never decide legal movement or damage.

Use checked arithmetic. Overflow rejects the operation with a diagnostic; it never wraps or silently clamps. Rule-defined caps are applied only at their named stage. Multipliers use basis points with signed 128-bit intermediates: aggregate flat modifiers, apply multiplicative groups in ascending definition-ID order, round each specified group toward zero, then apply declared caps. Damage floors and minimum costs are explicit rule fields. Dividing durations to schedule an action rounds upward. All serialization, string comparisons and parsing are culture-invariant.

The initial rules profile defines Strength, Agility, Endurance, Intellect, Will and Presence; Health, Mana and Stamina are resource pools. Skills and resistances are separate typed domains. Legacy values retain source data and use recorded transforms; a Squire/Mage/Scout is not discarded because the successor has a different derived-stat model. A check compares `d100 + skill + relevant attribute + modifiers` against a difficulty or an equivalently evaluated opposing result. The initiator loses a tie; exceptional success/failure thresholds are profile fields. Content balance can revise values through versioned rules, not unrecorded per-system formulas.

RNG v1 uses SHA-256 counter streams keyed by world seed, rules version, domain, responsible entity/event ID and draw counter. Read unsigned 64-bit words in defined big-endian order; use rejection sampling for bounded integers. Persist counters and accepted external decisions. Generation, NPC planning, loot, research and cosmetic variation use distinct domains; cosmetic RNG is excluded from authority. Changing frame rate, worker completion order or an unrelated actor's idle cannot perturb a battle roll. This straightforward baseline can be optimized only with equivalent golden vectors or an explicit version migration.

The host targets 20 scheduler steps per real second; this rate is a qualification parameter, not rendering authority. Within a step, process due state transitions/expiry first, accepted commands second, then observations, planning and scheduled follow-ups. Scheduled work sorts by due domain-time, fixed phase priority, domain ID, actor ID and stable event ID. Commands at a cutoff sort by durable ingress acceptance sequence, then command ID; clients cannot backdate them. Commands dependent on an earlier result submit against its revision. Replay reproduces accepted inputs/order; it does not promise identical results from differently timed human inputs.

Parallel workers compute immutable candidates. The authority waits for the scheduled candidate or slows the simulation; it does not select winners according to wall-clock completion. Search limits count deterministic work units. Initially allow 32 action candidates and 256 planning expansions per actor decision; defer blocked plans until relevant evidence changes or a scheduled retry. Preserve the queue and reason for delay. No machine may silently omit NPC decisions to maintain frame rate.

## 4. Transactions, saves and recovery

`CommandEnvelope` contains protocol version, command ID, principal/session, controlled actor, world/branch, expected revisions and typed payload. Authentication/control and knowledge permissions are checked before gameplay validation. Reusing a command ID with different content is rejected. Reusing it with identical content returns the original receipt, including a committed rejection. Retries do not reroll outcomes.

The core prepares a mutation plan against one committed revision. SQLite is the first storage adapter: one local database per world, one writer, WAL mode, `synchronous=FULL`, foreign keys and explicit transactions. Keep all branches participating in a transit inside that database. Store the command receipt, ordered events, entity deltas, scheduler/RNG changes and projection outbox in one transaction. Publish success only after durable commit; then swap the in-memory revision and deliver projections. SQLite's documented atomicity depends on storage/OS assumptions, and WAL is unsuitable as a casually shared network-filesystem database.[^3]

Example: two workers attempt to repair a ship using the last plank. `StartRepair` validates crew permission, damaged part revision, available plank/tool and worker obligation. One atomic commit reserves the plank, worker and station and creates the job. The second request receives `ResourceReserved`. Each legal work interval consumes time/tool condition and records progress. Completion consumes the reservation once, changes the same part's condition, records provenance and grants applicable learning. A crash after database commit but before acknowledgement returns the same receipt on retry. A crash before commit leaves neither a reserved plank nor half a repaired vessel.

Checkpoint canonical state every five simulated minutes or 10,000 commits, whichever comes first, plus explicit safe-save/branch operations. These initial frequencies are tunable. Persist enough continuation to replay from the checkpoint: definitions, commands, external decisions, clocks, pending jobs, scenes, claims and RNG. Canonical binary encoding uses schema tags, explicit lengths and sorted maps; SHA-256 state hashes cover all consequential fields. Schema-aware canonical JSON is the diagnostic representation, not an implicit reliance on JSON property order.

Backups use a consistent snapshot/backup operation, never an arbitrary copy of an active WAL file. A migration executes on a copy, pins required packages, validates invariants and atomically selects the migrated world only on success. Corrupt or unknown schemas fail closed with recovery choices; do not regenerate a seed over damaged history. Archive compaction must losslessly preserve arbitrary historical access: lived commands/events, causal state deltas, external decisions, clocks and required rule/package/generator versions remain reconstructable throughout the promised chronology. Indexes/checkpoints may be rebuilt or compacted, but no history interval is discarded because no active quest references it. Storage pressure triggers visible preparation limits/backpressure or explicit archival capacity work, never covert destination removal. Local/dedicated handoff preserves WorldID and exclusive writer ownership; divergent copies record an explicit fork.

## 5. Clocks and the adopted Wait contract

`CommitSequence` orders changes and is not a calendar. `WorldInstant` uses signed 64-bit days plus bounded milliseconds within a day, supporting eon-scale epochs without millisecond-counter overflow. Each branch has a calendar and epoch/rules identity. Tactical time uses integer readiness units. Cosmetic time belongs only to clients.

The initial world profile sets one complete day/night cycle to 2,400 authoritative exploration seconds: about 40 real minutes during uninterrupted normal play. At 20 Hz, each 50-millisecond exploration step advances 1,800 world milliseconds. Paused wall time contributes nothing. Movement uses the fixed step separately. Standard combat readiness is 100 units; delay is `ceil(10000 / effectiveSpeed)` for speed normalized to 100. Tactical progress advances five units per step without a required hold; 100 units equal one second of local effect/need exposure. Exploration and combat calendar rates intentionally differ. These pinned pacing values require human acceptance; animation length never changes them.

Default hosted policy is **pause when no gameplay-ready players are connected**, including offline time. A socket opening or unfinished snapshot/chunk restore does not resume an empty world; readiness requires the client to acknowledge its valid playable state. No automatic wall-clock catch-up occurs after restart. An explicitly selected always-running profile needs visible offline-care/deadline rules and qualification. Sleep/fast travel advances normal scheduled events; acceleration requires all affected connected controllers' consent and stops at a meaningful interrupt.

Rest is an actor activity with accumulated valid exposure, sleep quality, fatigue, shelter and interrupted progress. Recovery credits accrue from completed rest intervals against actual deficits; camp entry, departure and reload grant no full-reset bonus. Short respite can restore its declared resources without curing every wound or need. Daily sleep pressure and recovery rates are world-profile tuning, not compulsory frequent camping. Camp supports watches, cooking, care, repair, research, conversations and emergent events; assigned work consumes normal supplies and time and does not count as sleep. A watch's scoped perception can interrupt sleepers when a threat is noticed; damage and other declared interrupts also stop rest. Preserve partial recovery and unfinished jobs.

Time acceleration requires all affected controllers' consent, including outside players in independent co-op; one sleeping pocket cannot skip their world. Without consensus, rest advances at normal applicable time. Where available, the player may control an authorized consenting companion or manage other actors' camp duties. A separated player without that option must choose normal-time sleep, short respite or deferred sleep; this may be unsatisfying. P03/P04 human and virtual-build tests must examine that case and revise recovery/progression tuning if it fails. P02 calibrates the 40-minute day/night cycle; P03/P04 qualify useful rest frequency, interruptions and social play. No separate instant-rest clock is introduced.

| Mode | Required decision | Progress elsewhere | Calendar/effects |
|---|---|---|---|
| Solo or coordinated co-op | Shared branch pause | No gameplay action progresses in that branch | During combat resolution, the branch advances at tactical exposure rate; holds advance neither calendar nor effects |
| Independent co-op | Encounter pocket holds | Uncoupled actors, jobs, travel and institutions continue | Branch calendar continues; pocket exposure advances only with tactical progress, never by catch-up |

Independent mode deliberately permits local stasis and lost outside opportunities. It is not one physically uniform clock. While held, participants gain no healing, hunger relief, research, labor, repairs or regeneration; they also incur no retrospective hunger, aging, wear or damage when released. Resource durations retain their remaining exposure, rather than subtracting the branch date on exit. A visible calendar and world-news panel remain available during a hold.

Deadlines have one mandatory policy. `ParticipantDuration` obligations accumulate required unpaused exposure and extend by one named anchor participant's suspension intervals; personal quests default to it. Shared appointments default to `FixedWorldInstant`, as do elections and external sieges: they continue and can be missed. An explicitly negotiated shared duration obligation names exactly one clock anchor; every participant sees that same deadline and receives changes. It never sums suspensions across attendees. Every policy is visible at commitment acceptance, with notices during holds and attendance/resource revalidation when executing. Recurring obligations store occurrence IDs and one suspension ledger, preventing duplicate extensions across repeated encounters. A held person's offscreen dependants receive no suspension unless themselves coupled; delegated feeding/care uses an available caregiver and real supplies. Warnings expose risks before departure and during holds.

## 6. Encounter admission, hazards, merges and exit

State transitions are `Exploration → Confrontation → Staging → Ready/Hold → Resolving → Outcome → Release`. Authored triggers, contextual encounters and deck opportunities use the same entry transaction. It claims participants and coupled dependencies before hostile effects apply. Staging uses legal routes and preserves action costs; a blocked formation falls back to legal current positions. Camera/UI/audio continuity follows the [v0.5 presentation contract](../combat-transitions-and-timing-decision-v0_5.md).

The pocket includes participants, carried goods, attached effects, support surfaces and consequential coupled processes. An occupied vehicle includes the whole vessel, fitted parts, crew, passengers, cargo, mount/tow links and its motion-related collision support. A fire on that deck shares its time. A connected machine cannot produce outputs outside while its worker/power source waits inside. A remote workshop with independent workers/resources legitimately continues; party membership alone does not stop the entire economy.

An outside projectile, spell, trade, heal, boarding action or physical hazard submits an **admission intent before influence**. A queued intent grants no free attack or reservation of future resources. At an encounter action boundary, revalidate source existence, knowledge, stock, route and current state; an outside healer may have died or spent the potion meanwhile. Admission charges the normal action/preparation delay. A newcomer cannot enter ready to strike repeatedly by leaving/rejoining; outstanding cost, pursuit and cooldown remain attached to the actor.

Merge connected encounters at a boundary, in ascending encounter-ID order. Freeze both while rebinding; preserve each actor's remaining readiness/effect durations instead of resetting absolute counters. Expire already-due effects before admitting new actions. Combine required player decisions and close the dependency graph. Initial qualification thresholds are 128 tactical actors per pocket and 512 detailed actors world-wide. Exceeding either records a **shared-pause fallback** for the affected branch and a visible reason. The complete coupled set then progresses through deterministic sequential work slices, initially 64 actor/dependency evaluations per slice, with a persisted continuation cursor. No slice publishes a partial logical action; calendar progress waits for its complete commit. Required decisions use the same controller/handoff policy below. This sacrifices throughput, not participants or hazards; the thresholds cannot legally truncate a fleet or crowd. Unsupported dependencies are validation failures requiring a recoverable diagnostic pause, not a claim that shared pause solved them.

An active player has no automatic decision countdown. After a transport disconnect is confirmed, record `ControllerDisconnected` and a reconnect allowance of 30 seconds of host wall time as an external session event. Then, under the default agreed host policy, a permitted co-player assumes control or the character's conservative NPC controller chooses defend/retreat/legal survival actions. Reconnection requests control at a safe boundary. Wall-clock disconnect decisions are journaled; replay consumes those records. A connected idle player continues to hold unless the host explicitly reassigns control; this social limitation of unlimited Wait is disclosed.

Exit requires a legal flee/disengage outcome or completed encounter, with outstanding costs preserved. Before release, show current outside conditions and fixed-date consequences. Revalidate positions/supports and rebind remaining durations to the destination clock. Deferred hazards are evaluated from current state; do not apply accumulated invisible attacks or storm exposure. If the exit surface is currently dangerous, present that fact and admit it as the next tactical dependency before the player commits release. No silent teleport to a safe copy of the scene occurs. The suspension ends once; queued admission intents are revalidated or cancelled, never replayed blindly.

## 7. Space, generation and streaming

`WorldAddress` contains world, branch, realm/plane ID, signed 3D chunk coordinates, local integer coordinates and epoch reference. Sparse authoritative storage starts with 32×32×16-cell chunks. Each cell has versioned solid/material shape, remaining resource quantities, liquid capacity and environmental state. Validated integer shape definitions include empty/full cells, slabs, stairs and ramps. Footprints, body clearance, swept traversal, support contacts and line-of-sight intersect those actual shapes. Floors, subfloors, tunnels, bridges and rooms can occupy different Z positions above the same X/Y; climbing, swimming, flight and stairs require applicable capabilities and valid connections. Different realms have independent topology/rules and explicit portal edges. A selected camera floor never changes collision or traversal.

Render tiles and story regions are independent. Rebase visible Godot coordinates around a local origin, converting only nearby differences to floats. Vehicles use parent-local coordinates with stable frame IDs; reparenting is an atomic transform/custody operation. Collision/navigation uses the integer assembly volume, not sprite transparency. The selected presentation can remain pixel-art 2D; a second renderer does not require another terrain authority.

Mining is an interruptible work job against a material quantity/shape revision. Definitions specify hardness, tool compatibility/power, work requirement, energy/stamina, heat, tool wear, yield and byproducts. Invalid tools cannot progress through arbitrary hardness; magic uses declared excavation capabilities and costs. Partial work persists. Completion atomically removes the mined quantity, changes topology, creates conserved spoil/ore lots with source claims, and records tool/resource debits. Ore comes from pinned geological generation and remaining deposit state, not a new roll per mining attempt. Smelting, alloys and smithing preserve input quantities, losses, heat/fuel and provenance through ordinary process graphs. Tunneling vehicles call these same excavation rules and must clear their full swept volume; an inaccessible or too-hard face stops movement.

Construction reserves real materials, labor and target volumes. Fortress orders use the same buildings, economy, NPC workers, authority and combat geometry as field play; there is no separately simulated fortress mode. Structural v1 uses integer mass, material condition, rated bearing capacity and definition-specific span/bracing rules. A validated directed bearing graph transfers loads to supports/foundations in stable ID order, distributing integer shares with deterministic remainders. Natural rock has declared stable strata and unsupported-span limits; placed beams, arches and cantilevers require supported templates. Unsupported cycles cannot self-support. This is a rule-based structural simulation, not a universal stress solver. Mining a bearing cell or damaging a beam recomputes affected dependencies; instability creates explicit collapse/fall events and conserved debris. It does not silently vanish or become permanently weightless. Full affected components use bounded sequential work with persisted continuation; exceeding a work slice delays completion, never omits distant supports.

Liquids use conserved integer volume, per-material flow limits and transfers proposed from the previous committed step. Allocate proposals by downward-before-horizontal phase, source address, then destination address. Each accepted edge reserves both its source's remaining starting volume and its destination's remaining starting capacity; this step cannot spend promised incoming liquid or capacity from an uncommitted outflow. Thus competing inflows cannot overfill a receiver. Keep rounding remainders. Placement reserves valid displacement or rejects; it cannot delete water. Declared heat sources, sinks and material reactions have explicit rates/outputs. Flooding, fire, smoke, heat and debris use scheduled hazards and encounter admission. Loaded views do not bound consequences.

An excavation/construction edit validates its complete write/dependency set, including occupancy, adjacent vertical cells, load paths and fluid borders. One transaction commits terrain/material changes, consumed work, revision bumps and required support/fluid/hazard work plus invalidations for clearance, navigation, light and visibility. Affected authoritative queries cannot use stale caches: rebuild or hold the dependent action until its required revisions are ready. The invalidation closure crosses chunk borders; unloaded neighbors are read/generated under pinned rules, never treated as empty, solid or consequence-free. Render updates may follow asynchronously from revisioned projections. Concurrent miners/builders revalidate against the winning commit; no double ore, trapped occupant from a stale placement, or client-only passage results.

The required [geological world contract](GEOLOGICAL_WORLD_DESIGN.md) defines continental/relief evolution, finite terminating catchment dependencies, stable material/site/feature identities, exact chronology, live-stage replanning, and source-budgeted causal fronts. The [fluid/ecology contract](ECOLOGY_AND_FLUIDS.md) extends this section with material-specific liquids/lava, phases, finite physical backpressure, seasonal vegetation, food webs, dispersal, bounded inherited traits and evolving biomes. These are canonical modules in the same authority, not optional descriptive lore.

Generation proceeds from shared macro constraints to hydrology, ecology, settlements/history and local placement. Pin generator/package versions and accepted AI artifacts. Derive border conditions from stable macro addresses before cell realization. Generate a cell’s initial realization once, then preserve the ordered history of geological displacement/deformation, material transport, ecological change and player/NPC edits. A time-varying baseline cannot be swapped beneath an old mutation overlay; stable substrate/site/material identities and revisioned spatial remapping reconcile affected edits explicitly. Loading order cannot reroll residents, rivers or rewards. A newer generator applies only under an explicit frontier/migration policy; old discoveries remain intact.

The address space can continue practically indefinitely, but a save contains a finite realized world. Before introducing a new region, produce a bounded coherent history package constrained by known neighbors, trade, migration and cosmology. Established individuals remain recoverable in detail. Uninstantiated potential populations are generation constraints, not secretly existing shallow NPCs. Once any person, cargo shipment, named ancestor or consequential claim is established, activation cannot invent or replace it. Follow the [GDD frontier policy](GDD.md#3-geography-frontier-and-historical-continuity) and [frontier research contract](../research-v0_7/frontier-streaming.md); keep required Aldermere content reachable under its designated starting fixture.

Cities consist of real residents, visitors, migrants and passing merchants with the same applicable actor depth, distinct home/route commitments and actual arriving/departing cargo. Surface streets, inhabited floors, sewers, caves and crypts share topology; shadow-realm connections are explicit portal edges. A 20,000-resident city is a candidate full-city qualification workload, separate from the 10,000-actor early benchmark, not a claim of measured support or a deletion cap. Measure the complete resident records, active/distant work, trade arrivals, evacuation and vertical access before accepting that profile.

Geological and ecological stages validate the current branch revision before commitment: changed dams, mines, occupation, source quantities or magical forcing invalidate uncommitted downstream predictions. Persist the immutable cause separately from the revisable propagation plan. A pending environmental flux retains finite physical storage/capacity; reservations alone are not storage. Full capacity propagates backpressure/overflow or widens the defined hold. Macro preparation requires a finite outlet witness and acyclic dependencies or an explicit bounded closed-reservoir component.

Detailed and coarse simulation use the same actors, jobs and effects. Exact routine batching integrates only until the next relevant interrupt; splitting the interval must give the same result. Distant warfare may use a declared aggregate resolver with committed participants, casualties and supplies. Resolver selection is recorded before outcomes; approaching with a camera cannot reroll a losing battle. Each interval has one owner and `lastAdvanced` marker.

Prefetch navigation/data and art separately using travel speed, visibility and measured p99 preparation latency plus margin. Pin encounter and vehicle dependencies across chunk borders. Godot background requests are polled before retrieving resources: its documentation warns that retrieving an unfinished resource blocks.[^4] Worker completion is not a generation seed. If authoritative data misses its boundary, visibly hold the affected simulation dependency and retain state; no invented encounter masks the stall. A client's optional visual lag does not authorize a server pause or extra gameplay rights.

The [generation validation contract](GENERATION_VALIDATION.md) composes typed proposals, hard constraints, soft variety/attention preferences, constructive witnesses and bounded precommit repair/pruning/rejection. Exact-seed failures and permitted reseeds are explicit. Validators never reroll committed actors, terrain or historical facts; runtime invalidation uses legal transitions.

## 8. Actors, society, powers and material processes

Every instantiated NPC uses the same applicable actor state and action legality as a player. Controllers differ; depth does not. Persist body topology, capabilities, health/needs, possession references, knowledge, learned progression, relationships, goals and commitments. Initial body contracts cover humanoid, quadruped, avian and reptilian families with typed attachment/contact points, locomotion and equipment compatibility. Content supplies supported variants through the [GDD art matrix](GDD.md#17-art-animation-audio-and-interface-contract), whose native pixel dimensions require P02 acceptance and do not define canonical spatial units. A new anatomy requires capability/animation coverage; a sprite name cannot imply flight or tool use.

Injury records identify affected anatomy, tissue/function loss, treatment and persistent consequences separately from cosmetic scars. Loss of an eye or arm changes actual senses, grip, action and equipment eligibility; unsupported equipment is dropped or reassigned through the custody transaction, never deleted or duplicated. Supported prostheses restore only declared capabilities. Serious anatomical losses are rare tuning outcomes; occasional scars are more common. Both survive save, exposure-clock changes and branch travel. Ordinary sleep cannot regrow missing anatomy. A defined restoration spell restores its declared loss/function when its explicit target, cost and conditions are valid; no hidden unhealable exception defeats that promise. Restoration of a living body is distinct from resurrection. Scar appearance may remain or be removed by declared treatment/player choice while causal injury history persists.

Directed relation edges store trust, affection, respect, fear, grievance and obligations with causes. Household, party, guild, religion and nation memberships remain separate. Recruitment changes actual commitments; an adventurer cannot simultaneously perform full-time remote labor. Joint actions reserve roles and costs atomically and define interruption, credit and stacking. NPC planners consume only their knowledge projection and feasible affordances. Public facts produce scoped evidence, then beliefs and decisions; hidden world truth is never a convenience planner input.

Persist individual desires, motivations, likes/dislikes and their causes separately from current needs and public reputation. Feasible plans score expected need relief, commitments, preferred activities, risk and relationship consequences using the actor's beliefs; hard legality/capability checks precede utility ranking. Personality affects thresholds, habits and deliberation without guaranteeing identical behavior forever. Experience can revise preferences and priorities through recorded events. Dreams may reflect those concerns without proving the underlying beliefs true.

Species histories separate cosmic affinity distributions, ancestry, culture and individual realization. Birth records pin parentage, epoch and variation draws. Later training, vows, transformations and exceptional affinities retain causes. Deities are first-class entities with domains, limits, knowledge, institutions, pacts and interventions; divine action uses declared capabilities and costs, not administrator mutation. A cult's claim and a deity's actual intervention are distinct records.

Lifecycle records persist biological development, age/exposure, species-specific needs, care dependencies, kinship and life/death state. Birth or other supported reproduction creates one stable identity and parentage/care obligations from a recorded process; retries cannot create another child. Pregnancy/incubation, maturation and biological aging advance by the applicable actor/process exposure clock: held coupled lives do not accumulate hidden catch-up, and offscreen lives use the same coarse-interval rules. Historical dates remain calendar facts; biological age may diverge under temporal play. Species profiles define applicable development rather than imposing a human lifecycle on every creature. Marriage/partnership commitments require eligible consenting individuals; legal/cultural recognition, kinship, adoption, household membership and affectionate relations remain distinct. Separation, bereavement and changed guardianship create actual obligations and memories.

`ResolveDeath` commits once: mark life state, revoke the deceased's living-body control/actions and personal office powers, interrupt their labor/concentration with declared waste/reservation policies, transition bodily remains, and place property in explicit body/estate custody. Individual identity, memories and causal references survive. Dependant care, claims, offices and promises enter defined continuations. Estate distribution and succession follow wills, law, eligibility and disputes, rather than universal immediate transfers to a player. Mandate survival follows its policy below. Legal state changes immediately; observers learn the cause through ordinary evidence, and rejection messages cannot reveal a secret death. An eligible spirit continuation requires an explicit `TransitionForm` on the same person with a fresh form-specific capability/control grant, permitted senses, containment/tether and exposure policy. It cannot reuse revoked bodily actions or create an independent inventory. Memory echoes, illusions and animated remains have distinct supported identities/authority. Resurrection restores the same identity under a declared body/life transition; it cannot clone property or undo completed inheritance, remarriage or succession. Those consequences require ordinary legal/social resolution.

Office hierarchies are typed authority graphs distinct from friendships or party order. A mandate names its issuer principal (actor, office or institution), scope, expiry, delegation and survival/revocation policy. Actor-bound mandates end with the actor; office/institution mandates survive a holder's death unless their declared vacancy rule revokes them. Death never authorizes the deceased to act. Already-authorized jobs by other workers continue only when their recorded job/mandate policy permits; ongoing intervals revalidate current rights without erasing legitimate completed work. Nested delegation is bounded and cycle-checked; councils and competing claimants use explicit rules. Vacancy, regency, election, inheritance, conquest and schism change holders without rebuilding society. Multiple loyalties remain possible. Detailed and distant simulation use identical legal records.

Castles, towns, crypts and dungeons are sites composed of ordinary terrain, structures, rooms, custody, inhabitants and hazards. Founding or expanding a polity creates a charter, offices, jurisdiction claims and obligations through actual people/resources. Building ownership, claimed territory, recognized sovereignty and effective control are distinct records: placing a castle never silently grants a nation. Recognition, policy orders, rebellion and conquest use diplomacy, mandates, supplies and enforceable actions; ground-level play remains in the same world.

Alignment uses typed ethical and autonomy/order axes, with declared values, observed reputation and cosmological obligations stored separately. Good/evil and lawful/chaotic/neutral labels summarize a chosen rules profile; they are not omniscient knowledge of an actor's motives. Acts, vows and transformations can change applicable values or cosmic contracts through explicit rules and evidence. Species/culture influences do not fix individual destiny or force planner behavior.

Markets hold actual stock, reservations, local demand, production and route/supply evidence. Versioned bounded price rules update on declared economic events/intervals; UI polling cannot move prices. Commodity, quality/condition, taxes, fees and bid/ask spread determine an integer quote, with issuer/principal, market/lot revision, quantity limit and visible fixed-world expiry. A quote alone reserves nothing. Acceptance atomically revalidates current stock/funds/rights, consumes its remaining allowance and transfers payment, fees and cargo custody. A reused or concurrently accepted quote cannot duplicate goods or exceed its allowance. Explicit forward/reservation contracts require real escrow/obligations. Institutional price policies follow mandate survival rules.

Buying in one town and selling in another is legitimate trade when transport, changed supply and total costs leave a margin. Caravans contain actual cargo, travelers, vehicles and hired guards with routes, wages, care and risk. Escort work/learning and payment follow real service; theft, delay, cargo loss, injury and death update contracts, claims and social consequences. Local prices and learned history/conditional forecasts are knowledge projections, never free global price omniscience. P03 retains a two-market quote/cargo/retry proof; P07 expands production, price shocks and early-to-midgame caravan careers.

Classes/jobs are versioned progression definitions with prerequisites, learning grants, proficiencies and specialization choices. Professions and offices are separate. Store retained learning per actor; class switching cannot erase or duplicate capabilities. Magic defines school, facets, delivery, targets, costs, concentration, duration, stacking and resistance. Illusion changes eligible perceptions; invocation produces its declared effect. Area, actor and object effects use common effect-instance ownership and clock contracts. Removing an enchantment removes its owned contributions, not unrelated later changes.

`ActionDefinition` unifies skill/capability prerequisites, applicable contexts, clock/time costs, resource/custody requirements, spatial/perception checks, effects, interruption, progression and semantic performance hooks. Fishing, hunting, cooking, knitting, writing, acting and acrobatics are explicit supported skill families alongside combat, magic and other professions. Their definitions need appropriate real affordances and outcomes; assigning a skill label is insufficient. Players and NPCs execute the same action contracts.

Exploration supports real-time action puzzles through the authority's fixed-step movement, collision and trigger rules. Puzzle state machines bind real switches, moving surfaces, skill actions, items/elements and cooperating actors; changes persist in ordinary objects/topology. Entering Wait couples consequential puzzle motion and hazards before effects commit, so a trap cannot kill held actors on a separate puzzle clock. Timing windows, readable anticipation, assists and alternate solutions are versioned accessibility/design parameters. No puzzle-only physics authority or combat-mode reversal is introduced.

Crafting, cooking, herbalism, alchemy, spell research and vehicle construction share a typed process graph: ingredient predicates/quantities, tools/catalysts, station, knowledge, worker roles, staged time/environment, outputs, quality, waste and interruption. A job reserves actual lots and labor. Substitutions and research return explainable properties; accepted discoveries become immutable, versioned definitions with provenance. Evaluation v1 permits at most 64 graph nodes, depth 16, 32 directly affected actor/effect targets and 256 emitted follow-ups per action. Cycles require explicit bounded iteration. Larger powers and terrain edits use staged region jobs with declared costs, not hidden limit bypasses.

Persist inventory preferences and reservations per authorized owner/controller. Automatic ingredient selection excludes equipped, favorited, explicitly protected heirloom and user-reserved lots by default; protection follows split/merged lot provenance unless explicitly changed by an authorized command. A preview lists the actual known items/quantities and costs before a permitted explicit override; overriding preference cannot bypass ownership, equipped-use eligibility or another job's reservation. Protection explanations use visible designation and acquired knowledge, never a hidden quest/artifact flag that reveals undiscovered importance. Retries and concurrent crafting revalidate both lot and preference revisions before reservation/consumption.

Forage plants and cultivated crops share persistent species/individual or material-patch records, growth/harvest intervals, soil/water/light requirements and renewable provenance. Harvesting cannot duplicate a patch's yield. Herbal teas compose ingredients, water, brewing heat/time and owned effects; hot springs expose bathers to actual water/heat/mineral conditions and bounded recovery/status effects. Enchantments modify declared material, plant, item or actor capabilities under the same effect rules. None grants an unconditional rest reset or substitutes for feeding/care.

Condition combines elapsed exposure with discrete incidents. Persist material-specific wetness, corrosion, fatigue, temperature and repair state; integrate rates only over their owned exposure interval, retaining fractional remainders. A strike, fire burst, avalanche or sabotage commits a distinct damage event once. Event damage and continuous burning may coexist only through separately defined contributions; the same causal debit cannot be counted twice. Both paths can change structural support, performance and visible appearance. Repair restores declared function using work/materials while preserving age, provenance and remaining irreversible changes.

Vehicle assemblies contain typed sockets, structural/material condition, propulsion, steering, capacity and optional systems. Support boats/canoes/ships, carriages/chariots, dwarven tanks, sandships, tunneling ships, balloons and airships through profiles. Tunneling consumes energy/tool condition and commits excavated material and terrain; it does not noclip. Weather, load and damage alter declared performance. Salvage and part replacement preserve ownership and history.

Mounts, pets and familiars are actors with diet, care, training, bond, fatigue, injury and supported agency. Equipment and cargo remain items. Mounting/boarding validates anatomy, load and consent/control, and stores one attachment relation. Feeding consumes real food; delegation reserves a caregiver/supplies. Dismissal is a route, habitat or supported magical transit—not deletion. Recall, death, transformation and resummoning preserve or explicitly transition identity and possessions. No second familiar appears after reconnect.

The [cultural/lifecycle contract](LANGUAGE_AND_AFTERLIFE.md) adds actor-specific language/register comprehension, evidence-based background influences on directed relations, functional architectural/craft traditions, very slow species-appropriate aging, and accountable death/afterlife forms. UI localization never grants language knowledge. Calendar destination is distinct from biological exposure; player/NPC parity includes natural death and supported continued forms. Cultural affiliation does not instantly rewrite personality, knowledge or built material history.

## 9. Narrative, knowledge, branches and packages

Multiple grand arcs, personal stories, contextual encounters, adventurelets and decks coexist as separate instances. Eligibility binds real participants, places, beliefs and resources. A deck draw records its RNG, chosen definition, cooldown and consumption; failure revalidates and draws another eligible opportunity or none. It never creates a replacement shipment or resurrects a giver. Shared actors/resources connect arcs through normal events. A dark lord may not arise; NPCs may defeat, join or outlive a threat. Captivity/occupation has actionable escape, rescue, negotiation, service or succession continuations.

`ChallengeAssessment` evaluates a vector of capabilities, check difficulties/opposition, learned information, tools, consumables, party roles, timing, environment and realm access for quests, puzzles, enemies and obstacles. A suggested tier is a summary, not a universal scalar that proves solvability. `GenerationWitness` pins seed/rules/definitions, starting-state assumptions and at least one feasible chain of actions, costs and dated conditions through relevant spaces/times/planes. Its privileged validation data never enters ordinary forecasts. Optional hard challenges, concealed gates and intentional dead ends are declared content roles; the critical intended progression still requires a witness.

Events revalidate witness assumptions and narrative eligibility. Lost resources, changed allegiance or a missed window can produce an actual alternate route, renewed work, recurrence, failure or another declared continuation; they cannot manufacture a victory or replacement NPC. Recurring windows have stable occurrence IDs and visible timing where known. Time-based progression may coordinate parallel actors/events without resetting the world or imposing a universal final deadline. Player-facing hints/forecasts derive only from acquired evidence and mark uncertainty. P03 retains a small combined capability/time/realm proof; later production measures progression across complete chains, not isolated encounter ratings.

Narrative owns interpretation and phase, not armies, inventory or completed quest facts. A source-faithful migration fixture demonstrates original quest reachability; a later autonomous outcome legitimately changes that route and produces its declared continuation. Concurrent turn-in uses the same command receipt/custody transaction. Scene direction requests semantic actions; skip, restart and late join reconstruct the committed phase without replaying rewards. Cosmetic completion cannot decide when an attack is legal.

The [audio contract](AUDIO_DIRECTION_AND_RUNTIME.md) consumes permission-scoped semantic actions and context through Godot presentation. Location/mood/weather/time and encounter transitions drive authored layers/fades; spatial effects use permitted source/enclosure/medium information. Cues cannot expose private facts, create an actor or become action authority. Replay/rejoin restores current sustained context and suppresses stale/duplicate one-shots; appropriate cosmetic audio may continue during Wait.

Server projections filter before serialization. Per-principal views distinguish observation, belief, inference and administrator truth. Secret memberships, unrevealed coordinates and hidden inventories are absent from ordinary packets, tooltips and diagnostic logs. Default views show practical choices, essential known hazards/costs and readable consequences in the accepted JRPG style. Learned inspection skills progressively reveal justified properties, recipes, rule explanations and conditional forecasts from that actor's evidence. Expert detail never exposes hidden truth, another actor's secrets or future RNG; forecasts state uncertainty. Basic and expert views submit the same commands to one authority, and progression never requires spreadsheet micromanagement. More knowledgeable NPCs apply the same acquired knowledge and action system. Optional AI receives only allowed context and returns typed proposals without direct mutation. Persist accepted output/validation; replay and offline play never ask a provider to recreate them.

Temporal access covers any requested canonical millisecond `WorldInstant` from the world's defined historical origin through the selected branch's known head, at any valid world address. Checkpoints are accelerators, not a list of permitted destinations. `HistoryService.Prepare(address, instant, branch, headRevision, optionalCommitCursor)` pins the committed head revision at request acceptance and reconstructs from an earlier checkpoint/keyframe. Include events with authoritative time at or before the requested instant and sequence at or before the pinned revision/cursor, in stable commit order. All same-instant commits through that boundary are included by default; an optional cursor selects an earlier sub-event boundary without changing the date. Retain partial-interval exposure/remainders. The resulting prepared reference is immutable across retries, and child creation uses that exact prefix; later live commits cannot move it. An unprepared date/place enters visible progressive preparation, never rounding to a named era. Lived history uses preserved commands/events/state deltas and versioned interpreters; branch prefixes may share storage.

Pre-start ancient history uses a versioned hierarchy of cosmological, geological, climatic, hydrological, ecological, civilizational and local process/event generators, causal indexes and keyframes. Exact queries reconstruct their coupled intermediate state and local suspension history. Canonical solver schedules and remainders are independent of requested interval size. Branch interventions and ordinary live edits recompute affected endogenous futures rather than replaying invalid parent or previously predicted outcomes. Fine realization is lazy and deterministic from stable addresses/event identities, constrained by every established fact, lineage and resource claim. Query order must not change the resulting past or invent a replacement ancestor. Generated prehistory is a coherent recorded construction, not a claim that every millisecond of eons previously ran through detailed simulation. P03 requests several initially unprepared instants in different orders, across restart, and compares identities, facts and boundary exposure; P10 qualifies the entire available chronology, archive growth and preparation workloads.

Materialize a writable child before the first local historical interaction; untouched visits need not become permanent branches. The child preserves the factual prefix and then permits new consequences, without blindly replaying invalidated parent-future events. Source worlds and other players' histories are never retroactively overwritten. Future acceleration operates on an authorized destination head with consent/interrupts; arbitrary past access does not assert perfect future prediction or arbitrary merging of divergent histories.

A dream realm is a versioned `DreamSession`, seeded from its session identity and scoped dreamer beliefs, memories and imagination. It is not an unrestricted query over world secrets. Entry requires an acquired capability and declared permission/resistance/host policy. The avatar is a tethered projection of the same real actor; body, inventory, learning and authoritative resource pools are not cloned. Session overlays and symbolic figures/items are explicitly dream-only. Dreams can misremember or invent scenes; recovered impressions retain uncertainty and cannot silently become verified facts.

The session clock is anchored to the dreamer's sleep exposure. Visitor tethers and consequential bodily needs, hazards and interruptions join its dependency graph. Wait follows the existing admission rules rather than leaving a vulnerable body on an unaccounted clock. Waking, interrupted sleep, death or session collapse commits a safe exit for all affected projections to their actual bodies/locations, preserves pending physical consequences and revokes session-only abilities. It grants no teleport, healing reset or invulnerability. Effects, acquired memories and researched dream powers persist only through approved typed operations/costs. Symbolic ore and equipment cannot become physical cargo. Nested dream depth initially permits two sessions per tether, with cycle detection and ordinary portal/admission checks; deeper content requires an explicit qualified profile. P03 proves one real tether and interrupted exit; P10 expands authored/procedural dream play.

Transit is one database transaction covering source removal, destination admission, permissions, return anchor and receipt. Its dependency closure includes boarded vehicles, crew/passengers, mounts, tow links, cargo, attached effects and coupled jobs. Each affected player explicitly consents; NPC agency and portal capacity/environment rules are validated. An unsupported or unconsented group is rejected before departure; explicit legal disembark/detach actions may change the group. Preparation reserves the closure, revalidates it at commit, and converts remaining durations once. Alternate selves have different branch incarnations; one live traveler exists in one location.

Cross-branch cargo requires provenance and import eligibility. Origin claims attach to source reservoirs before extraction: deposit quantity intervals and renewable source/production-cycle intervals inherit their identity through forks. Mining the same copied vein using different command IDs cannot mint different export rights. Splits partition claims; transformations and merges preserve their union, without multiplying allowances or laundering them through waste/byproducts. Unsupported provenance refuses export. A world transit ledger assigns each exported interval's authority once; returns and subsequent authorized travel move that custody, not mint another allowance. Destinations reject duplicate claims/unique artifacts in preflight rather than deleting counterparts. Ordinary branch-local use remains local; inter-branch exchange is deliberately stricter. Knowledge and eligible blueprints transfer as learned facts; material and quest cargo require explicit permissions/costs. Retain an exploit fixture that forks before extraction and harvest, processes both copies, attempts export, returns and retries transit after a crash.

First-party and community packages use the same namespaced typed definitions, effect operations, generators and presentation manifests. Dependency versions/load order are pinned; ambiguous overrides reject. Ordinary packages cannot execute unrestricted C#. Additional native verbs require reviewed engine extensions with version/migration tests. Accepted in-game creations compile through the same validators. Upgrade/removal runs impact analysis on instances/arcs/branches, migrates a backup copy, and retains a compatible fallback or refuses removal; it never substitutes null references.

The [introduction contract](PLAYER_EXPERIENCE_AND_ONBOARDING.md) keeps the teaching graph separate from causal progression, assistance preferences separate from actor knowledge, and opportunities separate from accepted task reservations. World generation supplies actual valid bindings; the director only selects and presents eligible guidance. It cannot own NPC choices, rewards, clocks or emergency supplies. Endgame delegation uses the same feasible actions, real agents, budgets and exception handling as direct play.

The [local reuse decisions](LOCAL_REUSE_DECISIONS.md) identify bounded source mechanisms and tests worth adapting. Stable identity, conserved quantities, canonical scheduling, scoped observations and historical compatibility govern acceptance. No imported scene clock, weak-object receipt, global RNG or regenerate-on-load save path becomes a second authority.

Host communication exposes authenticated zone/system-message delivery with explicit channel membership, bounded message size/history, receipt/deduplication and safe rendered text. Reconnect supplies the declared recent window; player chat is not the canonical NPC-knowledge log. Diegetic speaking or sharing submits an ordinary actor action, with comprehension and observer scopes. A permission-scoped system notice must not disclose a hidden death, faction or event through its routing/reason.

Management policies declare stockpile filters/minimum/maximum levels, capacity and protected/reserved goods, job priorities, actual shifts, district roles and accountable delegates. They generate feasible ordinary jobs under recognized authority, actor commitments and exposure/care constraints. Revalidate stock/worker changes rather than duplicating a job or reserving unavailable input.

## 10. Adapters, invariants and evidence gates

The first network adapter uses reliable ordered WebSocket messages, TLS for remote sessions, protocol/package handshake and authenticated actor control. Solo uses the same envelopes over an in-memory transport. Send committed deltas at up to 10 Hz and full recovery snapshots by revision; clients interpolate and may predict reversible movement, but reconcile to authority. Four-player support does not imply an unrestricted public MMO, cross-server economy or automatic NAT traversal. Hosted connection/relay conveniences can evolve behind the transport boundary.

Godot owns rendering, input mapping, UI, audio, camera, asset loading and performance cues. Batch projected updates and keep animation state rebuildable. Dedicated server execution needs no Godot renderer or scene. Godot's documented headless export remains available for integration checks, not a second mandatory production host.[^5] Artist tasks own editable assets/metadata and acceptance; engine tasks implement stable import/performance contracts. Virtual playtesters use ordinary commands plus separately authorized diagnostics; independent critics examine traces and rendered evidence. Human enjoyment/style acceptance remains distinct.

Invariant checklist: one live location/controller authority per actor; one owner per item/interval; no negative unpermitted balances; every mutation has a cause/receipt; no package/version drift; equal legal rules for player/NPC; no hidden-fact projection; no render-driven outcome; no unaccounted cross-clock influence; no source-history overwrite; no migration omission disguised as procedural replacement.

| Failure | Required behavior and retained evidence |
|---|---|
| Retry, concurrent consumption, lost acknowledgement | Return receipt; exactly one resource/relationship/reward effect |
| Disk failure or partial checkpoint | Stop authoritative progression, preserve last durable revision, recover without seed reset |
| Bad package or recursive power | Reject with bounded trace before mutation; existing world stays loadable |
| Missing scene participant or blocked path | Cancel/rebind by declared arc policy; release reservations once |
| Slow generator or exhausted scheduler quota | Retain queue/identity, slow or expose synchronization; no hardware-dependent omitted actors |
| Concurrent excavation, flooded subfloor or failing support | Conserve quantities; invalidate dependency closure before affected actions; resolve complete queued hazards across chunk boundaries |
| Long Wait, disconnected participant, moving support | Apply §5–6 contracts, revalidate admission, preserve costs and visible outside consequences |
| Death/birth retry, disputed estate or resurrection | One identity/lifecycle transition; explicit custody and succession; no inherited-item cloning or retroactive social rollback |
| Branch/cargo conflict | Reject before departure or complete atomic transit once; retain return route |
| Knowledge or permission violation | Reject and redact before packet/proposal generation |

P00 closes repository isolation and candidate pins; P01 closes executed desktop exports, storage and portable authority qualification, including 3D material/support and lifecycle/mandate schemas. P02 retains a real mutable stacked-terrain fixture: excavate below an occupied floor, construct supports/stairs, and traverse above and below after restart. P03 proves concurrent edits, cross-chunk support/fluid consequences, death/job/custody/office transitions, and birth/maturation through Wait, coarse simulation and restart. These precede broad P04/P06/P07/P08 expansion. P01–P03 also execute replay, crash/retry, player/NPC parity, two-client Wait/vehicle/hazard/deadline cases, temporal transfer and package migration, as specified in the [production plan](IMPLEMENTATION_PLAN.md) and [validation register](VALIDATION.md). The initial qualification workload is 10,000 realized actors, up to 512 detailed actors pooled across four players and four progressing branch heads; saved identities/branches remain beyond the active budget. Measure CPU, memory, storage, queue latency and content throughput before promising that envelope on a named minimum machine. Failure requires optimization or explicit profile/plan revision, never quietly weakened actor depth.

Calendar rate, balance coefficients, chunk size, animation durations, asset density and checkpoint frequency are controlled tuning values with regression tests. Exact OS versions, hardware floors, package patch pins and population/storage envelopes are qualification gates. Clock ownership, arithmetic, custody, identity, branch policy and knowledge authority are decisions made here. Any later change to those contracts requires a recorded decision and save/replay impact review. The production plan maps every requirement through full release and later mobile support; none is waived by this technical sequencing.
